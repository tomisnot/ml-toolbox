## 2. 重启后必须验的行为（**便宜 → 贵**，命令可直接粘）

> 前置：**权威已重启**（新代码生效）。下面的命令都在仓根跑。

### 2.1 【最便宜，秒级】`logs_tail` 能读到网络代码里的 `print`
```powershell
python -m pytest tests/test_ml_mecha.py -q -k "job_stdout or concurrent_job_logs or log_buffer or native_fd"
# 期望 4 passed（readable / 并发不串 / 有界 / fd 边界）
```
人侧等价：`submit_run` 一个会 `print` 的网络 → `read_job(job_id, logs=20)` 看 `logs_tail`。

### 2.2 【便宜】`lr_by_group` 出现且**两组不同**
```powershell
python -m pytest tests/test_ai_efficiency.py -q -k "per_group_learning"
# 期望 1 passed（两组 lr 都出现、与 configure 一致、且**两者不同**）
```
人侧等价：网络 `configure` 分两组给 `name="amp"/"phase"` 与不同 lr →
`describe_training(run_id=…).lr_by_group` 应当给出 `{"amp":…, "phase":…}`。

### 2.3 【便宜】`curve` 默认变小（回执字符数）
```powershell
python -m pytest tests/test_ai_efficiency.py -q -k "curve_default_is_bounded"
# 期望 1 passed（brief 的 curve < all 的 35%，整份 < 70%，绝对省 ≥3000 字符）
```
人侧等价（拿一条真 run）：
```powershell
python -c "import sys,json; sys.path.insert(0,r'D:\code-nosync\Mechine learning'); from ml_mecha.engine import MLEngine; q=lambda m: len(json.dumps(MLEngine._query_training_detail(None, run_id='<你的 run_id>', curve=m), default=str)); print('brief', q('brief'), 'all', q('all'))"
```

### 2.4 【中】`best_metric` 声明 ⇒ `best.pt` 按它选（并报口径）
```powershell
python -m pytest tests/test_nqs_path.py -q -k "best_pt_selection or periodic_best_pt"
# 期望 2 passed（声明生效/未声明逐位不变/方向不许猜；周期也写 best）
```
人侧验收：`checkpoint_detail(run_id=…).files_meta.best.best_by`
应给出 `{"tag": "<你声明的>", "direction": …, "value": …, "epoch": …, "step": …}`，
并有 `val_loss_best` 作对照。

### 2.5 【中】`checkpoint_every` **端到端**：训练**进行中**盘上就有 `last.pt`
```powershell
python -m pytest tests/test_nqs_path.py -q -k "checkpoint_is_written_periodically"
# 期望 1 passed（另起线程轮询：训练**还活着**时就看到 last.pt）
```
人侧验收（长训练）：
```jsonc

// 训练中途：
checkpoint_detail(run_id=…)     // 期望 available=true + last_saved.saved_at_step 是**当前步**（小于总步数）
```

### 2.6 【中】`resume_from` 起始 loss 贴近断点
```powershell
python -m pytest tests/test_nqs_path.py -q -k "resume_from"
# 期望 1 passed（自归一化比较 + 三种可教学拒）
```
人侧验收：拿上一轮的 `run_id`：
```jsonc

// 回执应当有 resumed_from / resumed_which / resumed_at_step；
// 而 describe_training 的 loss 首值应**贴近上一轮末值**（实测量级：99.68 vs 从头 1017.6）
```

### 2.7 【要知道，不必验】fd 边界
`logs_tail` 是空**不代表**没报错：**C 层（torch/CUDA/OpenMP/MKL）与子进程直接写 fd 1/2 的输出
抓不到**（那类报错只出现在权威控制台/日志里）。
要对齐：用 `read_job` 的 `started_at`/`finished_at` 去权威那段时间的原始输出里找。
（本轮**故意没做** native 桶，理由见 `pitfalls.md` A56：风险 A/B + 代价 C。）

## 4. 已知边界（**会误导后人的那些**）

1. **`logs_tail` 只看得到 Python 层的 `print`**；C 层/子进程写 fd 的**不在里面** ⇒
   **空 ≠ 没报错**（见 §2.7 与 A56）。
2. **`run_id` 自动去重，但显式 id 不去重**：显式给 `run_id` 的调用方（GUI 就地重跑、
   固定 id 的判据/探针）会**照旧往同一个 `runs/<id>/` 追加** —— 那是他们要的语义。
   只有**自动生成**的 id 撞上已有内容时才改用 `-b<k>` 并留痕。
3. **`best.pt` 未声明 `best_metric` 时按 `val_loss` 选**（与从前逐位一致）；
   `best_by.tag == "val_loss"`。自定义任务的主指标常常**不是**它（实测 `best` 0.6464
   vs `last` 0.8174）⇒ 想要主指标口径就显式声明。
4. **`checkpoint_every` 的单位是"优化步"**（表格/负载路径），
   ⚠ **图任务里 1 epoch = 1 步**（整图前向、没有 batch）。
5. **周期 `best.pt` 最坏晚一个周期**：它在"最佳轮刷新后的**下一个**周期"落盘
   （不是刷新那一刻）—— 被中断时，最坏情况是"少了最后 N 步内的那次刷新"。
6. **`resume_which="best"` 装的是 `best.pt`**（按 `best_metric` 或 val_loss 选的那份），
   与 `last` 不是同一轮；回执的 `resumed_at_step` 会说明它落在哪一步。
7. **`target_kind` 是推断的**（数值且**基数 > 20** 才算回归）⇒ 一份连续但取值很少的目标
   会被判成分类；`prepare_dataset` 的 `target_kind_reason` 会说清依据，
   而默认管道的**分层抽样**在"每类只剩 1 个成员"时会报
   `stratify_on_low_cardinality_target`（可教学）。
8. **`.dsh/skills/ml-toolbox/` 是 `skills/ml-toolbox/` 的 junction** ⇒ 只有**一份**文件，
   别再做"两份同步"（`Copy-Item` 会撞系统拒绝）。
