# 设计：长任务编排与身份台账

> **把"会话态"升级为「项目台账 + 调度器 + 契约化真相」。**
>
> 动机（使用者的原话）：*"当前最主要的摩擦不是'某个功能缺失'，而是'AI 作为编排者，
> 无法有效地等待与追踪'……这三件事合起来，把'24 小时无人值守'变成了'人必须在旁边
> 一遍遍说跑完了'。"*
>
> 本文不逐条满足需求，而是先找出**反复长出这些需求的四个系统属性**，再用三层机制
> 让需求被**构造性覆盖**（表 §6 是证明：每条历史需求都能指到一个机制，而不是补丁）。
>
> 依据：`需求-在ML工具里训练神经量子态.md`、`反馈-NQS路径实测缺口.md`、
> `建议-AI往返成本与训练观测面.md`、`反馈-code_path接线与dry_run实测.md`、
> `反馈-观测面默认全量与AI调用预算.md`、`建议-ML工具长任务编排与失败可读性.md`、
> `原子模拟对接.md`（调参业务线）、`优化契约.md`、`项目定位.md`。

## 0. 诊断：不是"缺功能"，是缺四个系统属性

七轮反馈里出现的条目（约 40 条）**全都落在这四条上**。它们是**属性**而非功能：
一条属性补齐，一整类条目同时消失；反之，按条目打补丁会一直长出新的同类条目
（本轮之前就是这么走的：`read_job` 摘要、`grad_layers` 摘要、`shapes_verbosity`
是**三次**同一件事的补丁）。

| # | 系统属性 | 缺失时的表现（历史证据） |
|---|---|---|
| **S1** | **身份与持久**：一切实体有**内容寻址的稳定身份**，且台账落盘 | `dataset_id` 重启失效、重复登记 7–8 次、每次返回新 id（反馈③§3.4）；`job-1` 重启后指向别的任务（§3.1）；"这次跑的是哪份数据"只能靠记忆（§3.4）；`unknown_dataset` 静默死亡（反馈④） |
| **S2** | **等待与编排**：框架负责"等到终态"与"按序执行" | `wait_s` 上限 30 s ⇒ 十几次轮询，最后**改用本地 `pwsh` 睡 9.5 分钟**（建议⑤§2.1，**绕过工具=缺能力的最硬证据**）；并发上限 4 ⇒ 报错而非排队（§3.2）；"跑完 A 再跑 B"靠人肉（§3.5） |
| **S3** | **观测预算**：大字段默认摘要、截断可见、全量显式要 | 同一件事补了三次（`read_job.progress`、`latest.grad_by_layer`、`dry_run.shapes`）；缺 ETA/吞吐（§4.2）、缺里程碑（§4.3） |
| **S4** | **真相与资源**：失败必有可读真因；资源事前可估、事后可归因 | `state=done && error=="" && run_id==""` 这个组合存在（§2.2）；OOM 被报成 device assert（§3.3）；毒化提示埋在 hint 末尾（§2.2）；**临时注册竞态**（§2.3）；**用户被迫在自己的网络代码里手写分块**（§3.3） |

**四条属性各自的"自然形态"**（这是本设计的立足点）：

- S1 → 软件**已经**有内容指纹（`Pipeline.fingerprint()` = sha1 前 12 位）和落盘的
  `runs/<id>/record.json`（含 `dataset`/`pipeline_id`）⇒ 缺的只是**把指纹当主键**、
  以及一份**数据集/作业台账**。
- S2 → 软件**已经**有作业注册表（`assembly.submit()` 是唯一入口）⇒ 缺的只是
  让它**排队**、**能被等到终态**、**能执行一串步骤**。
- S3 → 已经有"摘要 vs 全量"的做法（三处）⇒ 缺的是**一处清单 + 一条约定**，
  让"新增大字段必须登记"成为**判据**而不是自觉。
- S4 → 已经有结构化错误（`kind/hint/suggest`）⇒ 缺的是**不变量**（不许存在"done 且
  什么都不知道"）与**资源的一等化**（估算/预检/归因/分块）。

## 1. 诚实边界（先说做不到的）

| 想要的 | 能不能做 | 结论 |
|---|---|---|
| **完成事件（服务端主动唤醒 AI）**（建议⑤§2.1 最优项） | ❌ **不能**：本框架的 MCP 面是**拉取式**，`mecha` 里没有 notification/sampling/elicit 能力 | 用**等价物**替代：① 长阻塞等待（上限提到客户端超时之内）；② `wait_any`；③ **链在服务端顺序执行**——AI 声明一次就能离开，"唤醒"这件事被**消掉**而不是被实现 |
| 重启后**恢复运行中**的作业 | ❌ 不能：Python 进程没了 | 台账标 `interrupted`；**链可续跑**（步骤幂等，已完成的跳过） |
| 真并行调参评估（12 核 / 8–12 进程） | ✅ 已有（`opt` 侧 `workers`） | 本设计不重写 `opt/runner`，只让**作业层统管**它 |
| 引入数据库 | 不需要 | 规模是几十~几千条 ⇒ `jsonl` + 原子重写足够；避免新依赖 |

## 2. 三层设计总览

```
┌─ L3 契约与真相 ─────────────────────────────────────────────┐
│  投影约定(一处清单) │ 终态不变量 │ 资源估算/预检 │ 框架分块 │ 一次注册 │
├─ L2 调度器 Scheduler ───────────────────────────────────────┤
│  队列(入队而非报错) │ 热改上限 │ wait="terminal" │ wait_any │ 链+续跑 │
│  稳定句柄：job_id | 作业名 | run_id                          │
├─ L1 台账 Ledger（落盘、内容寻址、幂等）───────────────────────┤
│  datasets: 指纹→id 幂等 │ jobs: 稳定名→记录 │ chains: 名→进度  │
│  runs: 复用 runs/<id>/record.json + 回显 dataset 指纹         │
└──────────────────────────────────────────────────────────────┘
        ▲ 全部落在工作区根：`.ml-mecha/ml_ledger/*.jsonl`
```

**层间唯一的写入口**：`MLMecha.submit()`（现在是 `jobs.submit` 的唯一调用点）
⇒ 调度器挂在这里，任何新命令**自动**获得队列/台账/不变量，无需逐命令接线。

## 3. L1 台账（身份与持久）

### 3.1 实体与键

| 实体 | 主键（内容寻址） | 别名 | 落盘 |
|---|---|---|---|
| dataset | `fp = sha1(source 声明 ⊕ pipeline_id ⊕ 行数 ⊕ payload 声明 ⊕ 划分口径)[:12]`；**id = `ds-<fp>`** | 用户给的 `name`（台账里记 aliases） | `datasets.jsonl` |
| job | **稳定名** `job-<slug>-<n>`（`n` 是台账里的**持久计数器**） | `run_id`（终态后） | `jobs.jsonl` |
| chain | 用户给的 `name`（唯一） | — | `chains.jsonl` |
| run | 既有 `run_id` | dataset 指纹 / 作业名 | 复用 `runs/<id>/record.json`，**新增回显字段** |

### 3.2 幂等（反馈③§3.4 的正面回答）

- `prepare_dataset` 先算指纹：**命中即复用**（回 `reused: true` + 原 id），否则登记新条目。
- 同一份数据登记两次 ⇒ **同一个 id** ⇒ "上一轮用的哪份数据"在会话/台账里**永不错位**。
- ⚠ 指纹是**声明级**的（路径 + 管道 + 行数 + 负载声明）。源文件**内容**变了怎么办：
  台账记 `size/mtime`，命中但文件已变 ⇒ 回 `source_changed` 并给**新** id（如实，不假装幂等）。

### 3.3 跨重启复原

- 装配时读台账；被引用的数据集若**可复原**（`source` 文件仍在 + 管道声明在）⇒
  **懒复原**：首次被引用时按声明重跑 `prepare`，成功后缓存为同一 `ds-<fp>`；
- 不可复原 ⇒ **明确回** `dataset_needs_reprepare`（附缺失原因），
  而不是现在这种"id 不认识"（反馈④的静默死亡源头之一）；
- 运行中的 job ⇒ 标 `interrupted`（诚实），链则可续跑。

### 3.4 回显（"这次跑的是哪份数据"永远可查）

`RunSummary` / `describe_run` / `describe_training` / `read_job` 都带：
`dataset_id` + **`dataset_fp`** + `pipeline_id` + `code_fingerprint`（自定义网络源码的 sha1）。
⇒ 任意 run 都能追到"哪份数据、哪条管道、哪版代码"，**不依赖对话记忆**（§5 的 run manifest）。

## 4. L2 调度器（等待与编排）

### 4.1 队列（§3.2）

- `MLTB_MAX_JOBS` 的语义从"上限"变成"**并发工作数**"：超出 ⇒ **入队**，
  回执带 `state=queued` + `queue_position`（不再报 `too_many_jobs`）；
- `set_job_limit(n)` **热改**（不需要重启；重启代价大是使用者明确指出的，§4.4）。

### 4.2 等待原语（§2.1 的次优项，但立刻可用）

- `read_job(job_id|name|run_id, wait="terminal", timeout_s=…)`：
  上限从 **30 s 提到 540 s**（客户端工具超时约 10 分钟，留余量）。
  ⚠ 超时**不是错误**：回"还在跑"+ 进度摘要 + ETA（这是"等待"而非"失败"）；
- `wait_any(handles, timeout_s=…)`：**第一个终态**就返回（"一把投多个、谁先完谁先报"）；
- 三种句柄都接受：`job_id`（会话内）/ **作业名**（稳定）/ `run_id`（终态后）。
  ⇒ §3.1 的"拿旧 `job-1` 读到别的 run"从根上消失（名字持久、且 `job-<n>` 的 `n` 也持久）。

### 4.3 链 = 无人值守的真正形态（§3.5 + §2.1 的替代）

因为**没有推送**，"AI 等着被唤醒"这条路走不通 ⇒ 把"等"从 AI 搬到**服务端**：

```jsonc
submit_chain(
  name="k_sweep",
  steps=[
    {"name":"k25",  "code_path":"net.py", "dataset_id":"ds-…", "overrides":{...}},
    {"name":"k60",  "code_path":"net.py", "dataset_id":"ds-…", "overrides":{...}},
    {"name":"k100", "code_path":"net.py", "dataset_id":"ds-…", "overrides":{...}}
  ],
  on_failure="stop"          // stop | continue | retry(n)
)
```

- 链由调度器**顺序执行**，每步落盘；AI 只需**声明一次**就能离开；
- 步的**幂等键** = `hash(step 参数 ⊕ dataset_fp ⊕ code_fingerprint)` ⇒
  已完成的步骤**不重跑**（`resume_chain` 因此是安全的重入）；
- 重启后 `read_job(chain_name)` 报"**3/5 完成**，第 4 步 failed（原因）"；
  `resume_chain(name)` 从第 4 步继续；
- 与 `on_failure` 三策略组合：`continue`（扫参数网格常要）、`stop`（有这个才有意义）、
  `retry(n)`（偶发失败，§原子模拟的"偶发失败不中断"）。

### 4.4 遥测（§4.2）

调度器按最近窗口算 `epochs_per_s` / `eta_s`，放进 `read_job` 回执
（使用者现在是自己从 `progress` 算的）。

## 5. L3 契约与真相

### 5.1 投影约定：一处清单，一条判据（S3）

- **单一入口** `_project(value, *, detail, name)`：大字段默认摘要 + **真实条数** +
  `truncated` + `detail="full"` 才给全量；
- **一张清单** `LARGE_FIELDS: dict[命令, list[字段]]`（`ml_mecha/projection.py`）；
- **判据遍历清单**：清单里每个字段都必须"默认有界 + 有计数键"，且
  **新增未登记的大字段会被判据发现**（扫回执尺寸上限）⇒ 从此不再"补三次同类补丁"；
- 顺带落地：`progress` 默认只回 `progress_latest` + **里程碑**（25/50/75/100%，§4.3）。

### 5.2 终态不变量（S4）

> **终态 job 必须满足：`run_id` 非空 **XOR** `error` 非空且 `kind` 具体。**

- 由调度器在收尾时**强制**；违反 ⇒ 记为 `silent_terminal`（这是一个**框架自检失败**，
  要显式报出来，而不是让 AI 看到"done 但什么都没有"）；
- 判据：构造"命令返回空回执"的假命令 ⇒ 必须得到 `silent_terminal` 而不是 `done`。

### 5.3 资源真相（§3.3）

- `estimate_run(...)`：给"**预计峰值显存** / 当前可用 / 判读"，数据来源：
  ① 网络自己声明的 `estimate(ctx)`（可选钩子，最准）；② 兜底启发式
  （负载字节 × batch × 峰值系数）；
- `submit_run` **提交前预检**：明显不足 ⇒ **可读拒绝** `cuda_oom_predicted`
  （带数字与三条建议），不再让它掉进 CUDA 层变成 device assert；
- 运行期捕获 `torch.cuda.OutOfMemoryError` ⇒ `cuda_oom`（带数字 + "减 batch / 开分块"）；
- **毒化提示置顶**（§2.2）：`cuda_context_poisoned` 的说明放 `error` **首行**，
  不放 hint 末尾（现在的实现放在 hint，够不到"置顶"的要求）。

### 5.4 框架级分块（§3.3 最实用的一条）

使用者为了不 OOM，**在自己的网络代码里手写了分块**（按 R 切块、按块累加）——
这是通用需求（"大负载 + 小显存"），不该每个用户各写一遍：

- `ctx["chunks"](budget_mb=…)`：框架按预算把**全量前向**（`metrics`/探针/评估）切成块，
  回执里报"**已分 N 块**"；
- 训练侧：`batch` 超过预算时**自动 micro-batch**（梯度累加），并如实报告；
- 判据：把"一次算全量"的网络在**小预算**下跑通（结果与不分块一致到容差内），
  且回执里有 `chunks` 字段。

### 5.5 一次注册（§2.3，竞态从根上消失）

- `custom_network` 在**装配时注册一次**；代码**按请求携带**（`cfg.extras`），
  不再"每次提交临时注册/注销"；
- 错误文案不再列 59 个方法（那是误导：让人以为方法名写错了）；
- 判据：**连续并发提交三个**自定义网络 + **取消后立刻提交** ⇒ 全部成功。

| §6 优先级三件 | 恰为 L2（等待）+ L3（真实失败）+ L1（台账） | — |

### 6.7 `原子模拟对接.md` / `优化契约.md`（调参业务线）

| 需求 | 机制 | 状态 |
|---|---|---|
| 单次 4–7 min、8–12 并行、错峰 | 已有（`opt` 的 `workers`/`stagger`） | ✅ 保留 |
| 偶发失败不中断 | 已有（P10 status=failed） + **链的 `retry(n)`** | ✅→**统一** |
| 预算/约束/交付 | 已有（`Budget`/`on_infeasible`/`OptRecord.best`） | ✅ |
| 产物与 ML 记录共存、可回看 | 已有（`runs/opt-*`） + **纳入台账**（同一 `describe_ledger`） | 升级 |
| "24 小时无人值守"（调参版） | **链 + 队列**（同一套机制服务两条业务线） | 新增 |

> **结论**：四条系统属性补齐后，两条业务线（神经网络训练 / 原子模拟调参）的
> "长任务 + 多轮 + 重启 + 交付"需求由**同一套**机制覆盖 —— 这正是"体系化"的意义。

## 7. 实施顺序与判据（依赖序，每阶段独立可用）

| 阶段 | 内容 | 判据（新增，均需红验证） |
|---|---|---|
| **P1** | L1 台账：指纹幂等、稳定作业名、指纹回显、`describe_ledger` | ①同数据两次登记同 id；②同一 root 两个装配（模拟重启）后按指纹复原；③`describe_run` 带 `dataset_fp` |
| **P2** | L2 调度器：入队、热改上限、`wait="terminal"`、`wait_any`、三种句柄 | ④超上限仍能提交且顺序正确；⑤`wait="terminal"` 真等到终态（不轮询）；⑥`wait_any` 返回第一个完成者；⑦按名字/run_id 查作业 |
| **P3** | 链：`submit_chain`/`resume_chain`、`on_failure` 三策略、步幂等 | ⑧三步链全跑且各步独立 run；⑨`on_failure=continue` 失败继续；⑩重启后续跑跳过已完成步 |
| **P4** | L3 投影清单 + 终态不变量 | ⑪清单里字段默认有界且有计数；⑫"空回执"命令 ⇒ `silent_terminal` 而非 done |
| **P5** | L3 资源与竞态：`estimate_run` 预检、`cuda_oom`、毒化置顶、框架分块、一次注册 | ⑬超预算配置被可读拒绝；⑭小预算下自动分块结果一致；⑮并发三连提交 + 取消后提交全成功 |

**每个阶段的收尾**：相关套件绿 + 红验证（每条判据"弄坏必须红、且红的理由对"）；
全部完成后跑一次全门。
