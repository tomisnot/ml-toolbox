## 1. 方法契约（`ml_toolbox/core/contracts.py`）

所有机器学习方法共享同一基类 `MLMethod`——这是"不同方法共享工具箱资源"的根本。

```python
@register                                  # core/registry.py 注册表
class MyMethod(MLMethod):
    name = "my_method"                      # 唯一键
    display_name = "我的方法"                # UI 显示名
    family = "ensemble"                     # 分组（UI 左栏按此归类）
    task = TASK_SUPERVISED                  # supervised|cluster|manifold|anomaly|timeseries
    target_kind = None                      # 'regression'|'classification'|None(双任务自适应)
    tags = ("fast",)                        # 搜索用；purposes 也由 tags 参与推导
    param_schema = [ParamSpec("alpha", label="α", kind="number", default=1.0, min=0)]
    accepts_aux = ()                        # 声明支持哪些辅助结构（图方法写 (AUX_GRAPH,)）

    def fit(self, problem, cfg, diag=False) -> MLResult: ...
    def predict(self, X, result): ...       # 监督方法
    def inspect_pages(self, cfg) -> list[PageSpec]: ...   # 可选：声明专属核心图
```

**新增一个方法 = 实现一个类 + @register，不改框架任何代码（G1）。**

### ⭐ `Problem` —— 观测 + 标签 + **观测之间的关系**（2026-10-03 范式扩张）

原接口是 `fit(X, y, cfg, diag)`。把全部方法族摊开看，**变的从来不是"数据有几个
参数"，而是"观测是什么、观测之间有什么关系"**：

| 族 | 观测 | 观测之间的关系 | 预测单位 |
|---|---|---|---|
| 经典监督 | 一行一个样本 | **无关**（条件独立） | 一行一个标签 |
| 时序 | 一个时间点 | **有序** | 一个时间点一个值 |
| 聚类/降维/异常 | 一行一个样本 | 无关 | 一行一个分数/坐标 |
| **图** | **一个节点** | **按边相连** | 一个节点一个标签 |

⇒ 四族的"观测单位/预测单位"完全一样，唯一变的是**中间那列**；而老契约只有前
两列，第三列无处安放（`Dataset.time_col` 是给它打的第一个补丁，还只是特命名字段）。
⇒ 现在统一收一个 `Problem`，方法只该用它的**三个视图**：

```python
X, y = problem.rows("train")     # 经典方法：就是原来的 (Xtr, ytr)
problem.X / problem.y            # 时序：整条序列（外生特征在 X 里）
problem.require("graph")         # 图：取边表；+ problem.masks() 拿节点掩码
```

- **`Problem` 承载 `DataSpec`**（`problem.spec`）⇒ 管道/存档/UI 一行不改；
- **能力要声明**：`accepts_aux = (AUX_GRAPH,)`；数据带了辅助结构而方法没声明
  ⇒ `problem.require` **结构化拒绝**（不许"悄悄扔掉"——`time_col` 时代
  "时序忽略外生 X"就是这么来的）；
- **`predict/evaluate/fit_extra_artifacts` 不变**（它们作用于**测试数据**，
  本来就是 `(X, y[, result])` 形状）。

### 辅助结构：`aux`（保留键 `AUX_GRAPH` / `AUX_PAYLOAD`）

```python
problem.aux["graph"]    # DataFrame，列：src / dst / weight(可选) + **任意特征列**
                        # src,dst 是**行号**（指向 spec.X 的行）⇒ 直接就是 edge_index
problem.edge_attr()     # (E, F) 多分量边特征（src/dst/weight 之外的列，按列序）
problem.edge_attr_names()   # 分量名（如 ['V_re','V_im','dist']）

problem.aux["payload"]  # {名字: 数组}，**每个数组第 0 维 = 行数**
problem.payload()       # 取逐行负载（没有就回 {}）
problem.payload_keys()  # 有哪些负载
problem.payload_facts() # {名字: {"shape": [...], "dtype": "complex128"}}
```

- **图任务不能按行切分**：训练节点会沿边"看到"验证节点（消息传递）⇒ 分数乐观化；
  切行还会让边索引失效。⇒ 用 `problem.masks()`（布尔掩码，**同一张图、只对指定
  节点算损失**）。这与时序的 `time_split` 是**同一类修正**（都是"行不独立"）。
- ⭐ **逐行负载与图是两种东西，别混**（2026-10-03，NQS 需求逼出来的区分）：
  - `graph` 说的是"**行之间怎么连**" ⇒ `partition_mode()` 返回 `"masks"`（不能切行）；
  - `payload` 说的是"**每行自带什么**" ⇒ **仍是 `"rows"`**（切行完全成立）。
    ⇒ `partition_mode()` **只看图**，不看 `aux` 是否非空（早先写成"有 aux 就是 masks"
    ⇒ 一带负载就误走图路径）。
- **dtype 是契约的一部分**：负载里复数就是复数、位串是整数、mask 是 bool
  —— 传输路径**不做 float 强转**（`to_numpy(float)` 会**静默丢虚部**，见 pitfalls A15）。
- 将来族各占一个键、**不动契约**：多视图 `aux["view_b"]`、序列掩码 `aux["mask"]`、
  元学习 `aux["episodes"]`。
- **没有标准标签的任务**：`spec.target_kind = "custom"` + `spec.y = None`
  ⇒ `can_handle` 只在方法**声明了消费负载**时放行；`runner` **跳过标准 evaluate**
  （并在 diag 写明理由），指标由方法自己上报（`Network.metrics` → TB 与回执）。


### 建模目的（purpose）维度

`task` 是"学习机制"轴，`purposes` 是"建模目的"轴（数模视角）。
9 个目的常量见 `contracts.PURPOSE_LABELS`：预测/判别/归因解释/分群/降维/
综合评价/异常检测/代理模型/参照基线。

- 默认由 `derive_purposes(task, target_kind, tags, family)` 推导（零成本继承）；
- 方法可 ClassVar `purposes=(...)` 显式覆盖；`m.purposes_of() / m.purposes_cn()` 读取；
- UI 方法库"用途"下拉按此筛选；tooltip 显示；
- 注意：tags 里的 `"baseline"` 是"该族默认起点"，不触发"参照基线"目的
  （只有 `family=="baseline"` 才触发，见 pitfalls L 备注）。

### 关键约定

| 约定 | 内容 |
|---|---|
| 参数 | 只通过 `cfg.resolve(param_schema)` 取；UI 覆写是运行级、不写回全局（P3） |
| 异常 | 方法内不抛出——`run_one` 捕获进 `MLResult.error`，遍历互不影响 |
| 诊断 | `diag=True` 才产出 `MLResult.diag`（结构化 dict）；默认零开销 |
| 评估 | 监督方法默认指标由基类 `evaluate()` 自动算（回归 rmse/mae/r2/mape；分类 acc/P/R/f1/auc） |
| 交叉验证 | 基类 `cross_validate()` 默认 k 折（分类自动分层），子类可覆写 |

## 2. 数据契约

- **单一数据入口**：`Dataset`（frame + target 列 + time 列），方法层禁止各自读文件；
- **管道**：`Pipeline.run(ds) -> DataSpec`，步骤链（缺失值→编码→缩放→筛选→划分），
  每步产出摘要 dict（含 `big_num` 大数字）存入 `spec.meta["chain"]`；
- **视图**：`DataSpec(X, y, train_idx, test_idx, target_kind, meta)` ——
  方法只消费这个，不感知文件与管道实现；
- **新数据变换**：`Pipeline.transform_new(frame, target)` 用 run() 冻结的统计量
  把新数据（如数模 test.csv）变换成与 `spec.X` 同构的特征矩阵（未见类别→全0列、
  缺失→训练期中位数、缩放→训练期参数、列自动对齐）；配合
  `method.predict(Xnew, result)` 实现"训练集选模型 → 测试集出预测表"闭环；
- **指纹**：`spec.meta["pipeline_id"]` = 管道配置哈希，实验记录可追溯
  （⚠ 已知边界：指纹**不含 `seed`**，见 `docs/pitfalls.md` A2 附带项）。

### 管道装配 —— 让 AI 组装预处理链（"自由的那半"）

默认链（中位数填 → one-hot → 标准化 → 8:2 切分）对多数题够用，但换策略、
加特征工程、改切分比例就没办法了。`prepare_dataset` 接受一份**可序列化的声明**
（JSON ⇒ 能原样进存档），两种自由度**都不破坏链式契约**：

```json
{
  "steps": [
    {"key": "missing", "params": {"strategy": "mean"}},
    {"key": "ratio",   "code": "class Step(StepBase):\n    def apply(self, df, target, diag=False): ..."},
    {"key": "scale",   "params": {"mode": "robust"}},
    {"enabled": false, "key": "feature_select"}
  ],
  "split": {"test_size": 0.2, "stratify": true, "seed": 7, "time_split": false}
}
```

- **配内置步骤**：`key` ∈ `{missing, encode, scale, feature_select, split}`，
  可调参数与取值域见 `core.pipeline` 的 `KNOWN_STEP_PARAMS` / `STEP_PARAM_CHOICES`
  （**单一真源**，工具 schema 与判据都从那里取）；
- **写自定义步骤**：给 `code`，里面定义 `class Step(StepBase)`；
  基类已注入沙箱命名空间（`StepBase`），实现
  `apply(self, df, target, diag=False) -> (df, summary)`；
  可选 `transform(self, df, target)`；
- **顺序 = 声明顺序**（那是作者意图，不做重排/去重）；`enabled: false` 跳过该步；
- **划分口径归 `split`**，**不在 `split` 步骤的参数里**——`SplitStep.test_size`
  与真实划分**解耦**是既有坑（`docs/pitfalls.md` A2），声明里 `split` 才是权威。
  实际生效的口径写进 `spec.meta["split_policy"]`，`describe_dataset` 报的就是它
  （**逐数据集**为真，不是引擎默认值）。

**四条纪律**：

1. **未知键/未知步骤/坏取值 = 硬失败**（不静默忽略——"设了不生效"是最坏情况）；
2. 自定义步骤**必须继承 `Step`**：`_fit_split_aware` 会把测试集喂给 `transform`，
   而基类默认抛 `NotImplementedError` ⇒ 不继承会变成"能 fit、到切分才炸"的延迟失败；
3. 没写 `transform` 时给一个**兜底**（对测试集再走一遍 `apply`）——
   ⚠ **只对"逐行、无拟合统计量"的纯变换成立**（造比值/取对数）；
   要按训练集统计量变换（均值/分位数）的，**必须自己写 `transform`**，
   否则新数据会被按它自己的统计量变换（**静默的错**）；
4. 代码**只经返回值交付效果**（不许自己写盘/碰 GUI），错误一律可教学。


### Network —— 让"拓扑"也自由（AI 写结构，系统管训练）

固定化的交给程序，自由化的交给 AI：**预处理与网络结构属于自由的那一半**。
`MLMethod` 的旋钮再多也表达不了拓扑（`torch_mlp` 的 `_build` 返回
`nn.Sequential` ⇒ 只能是线性链，残差/多分支做不到）。所以立一条**作者面契约**：

```python
class Network:                                  # ml_toolbox/methods/neural/network.py
    def build(self, n_in, n_out, *, nn): ...     # 必需：返回 nn.Module（任意拓扑）
    def loss(self, *, nn, n_out): ...            # 可选：默认按任务 CE/MSE
    def configure(self, model, *, torch, lr, weight_decay): ...   # 可选：自定优化器
    def forward_step(self, model, batch, ctx): ...                # 可选：特殊批次
```

- **谁写谁管**：调用方（AI）只写上面这些；切分、训练循环、进度、TensorBoard、
  artifacts、指标、存档、五页检视**全部由 `CustomNNMethod` 适配器代管**
  ⇒ 它跑的就是一台 `MLMethod`，既有设施一行不改（"神经网络是一种方法"语义不变）；
- **入口**：受控命令 `run_custom`（工具 `run_custom`），代码是字符串 ⇒
  JSON 可序列化 ⇒ 进 `runs/<id>/record.json` 的 `config.extras`
  （键 `custom_network_code`）；
- **按名字复用**：`describe_networks`（清单）/ `describe_network`（取源码）
  —— 改超参不必重贴代码，这是"自由"不变成"低效"的前提；
- **三条硬纪律**：① 代码**只经返回值交付效果**（不许自己写盘/碰 GUI/改 `runs/`）；
  ② 执行是**受控命令**（走 Gate 与审计），沙箱（`ml_mecha/sandbox.py`）负责的是
  "别把宿主搞崩 + 错误可读"，**不是**权限边界；③ **不静默**——代码抛错回
  结构化 + 可教学的原因。

## 3. 可视化契约（G2 高自由度所在）

### PageSpec —— 方法声明自己的检视页

```python
PageSpec(key="cm", title="混淆矩阵", kind="mpl",
         plot=lambda ax, result: ...,   # 纯 matplotlib，零 Qt（P1）
         hint="该方法不输出概率")        # 无数据时的语义化占位（模式 7）
```

- `kind`: `mpl`（plot 函数画到共享画布）/ `table`（消费 DataFrame 工件）/
  `text`（诊断文本）；`pg` 预留给 pyqtgraph 自适应组件；
- 方法未声明的页由 `runner.auto_pages(method, spec)` 按 task 兜底——
  **UI 永远有东西可显示，且兜底页与声明页走同一批 `methods/plots.py` 函数**；
- 共享页（指标/参数/诊断）由 `MLMethod.summary_pages()` 自动追加，方法无需声明。

### artifacts 键约定（UI 与导出按此消费）

| task | artifacts 键 |
|---|---|
| supervised | `y_true, y_pred, y_prob?, feature_importance?` |
| cluster | `labels, embedding, X_scaled` |
| manifold | `embedding, explained_variance_ratio?, labels?` |
| anomaly | `scores(越大越异常), labels(1=异常), threshold?` |
| timeseries | `t_true, y_true, forecast, ci?, horizon` |

## 4. 运行与持久化契约

- `runner.run_one / run_batch -> RunRecord`（方法+数据+配置+结果全留痕）；
- `persistence.save_record` 写 `runs/<run_id>/{record.json, artifacts.npz}`；
- **artifacts 支持嵌套结构**：`dict` 型工件（如 `nn_weights` / `nn_history`）存盘时
  按 `父__子__叶` 展平成 npz 键，`ui/history.load_run_record` 递归重组回 dict；
  多列 `DataFrame` 工件（如 `nn_layers`）拆 `<key>_values` + `_names`(+ 列数>1 时 `_cols`)；
- 对比视图排序依据 = `MLResult.primary_metric`（回归 rmse / 分类 f1 / 聚类 silhouette / 异常 auc / 时序 rmse）；
- **可选交叉验证**：`cfg.extras['cv_folds']>=2` 时 `run_one` 追加 `cv_<主指标>_mean/std`
  指标与 `diag['cv_scores']`（默认关，零开销 —— P3）；
- **实验可恢复**：`ui/history.py` 历史面板从 `runs/` 重建 `MLResult`
  （仅凭 artifacts 渲染检视图，不依赖 estimator），点载入即回看历史运行。

## 5. 入口脚本铁律（Windows 实测）

1. **lightgbm 必须先于任何 PyQt5 模块 import**（OpenMP 冲突 → access violation）。
   做法：入口处 `registry.load_builtin()` 放在 PyQt5 import 之前；
2. 离屏截图：CJK 字体显式加载、QMessageBox 打桩、grab 前同步 `canvas.draw()`；
3. 截图脚本的状态切换必须发生在截图 callable **内部**（构建列表与执行之间隔着主循环）。

### 检视页 kind 一览（PageSpec.kind）

| kind | 渲染 | 用途 |
|---|---|---|
| mpl | `plot(ax, result)` 画到共享 MplCanvas | 绝大多数核心图 |
| pg | `PGScatter`（pyqtgraph 滚轮缩放/拖拽） | 聚类/降维嵌入，大点量不卡（模式 5） |
| table | 消费 DataFrame 工件 | 指标/参数/特征表 |
| text | 只读文本 | 诊断产物 |
| nn_weights | 注册 builder（`ui/neural_pages.build_weights_page`） | 权重热图：层下拉 + 最终/初始/ΔW 视图 |
| nn_replay | 注册 builder（`ui/neural_pages.build_replay_page`） | 表示演化回放：epoch 滑块 + 播放 + 类纯度读数 |

**新页类型扩展（G2 自由度）**：方法层只声明 `kind` 字符串并把数据装进 `artifacts`；
UI 层用 `inspector.register_page_builder(kind, builder)` 注册工厂
`builder(result, spec) -> QWidget | None`（返回 None = 工件不足，显示 `spec.hint` 占位）。
方法层零 Qt，渲染逻辑全在 UI 层——新增一种可视化 = 注册一个 builder，不改框架。

### 神经网络可视化（方案 C：一半一半）

神经网络"中间发生了什么"仅靠 loss 曲线无法回答。方案 C 用 `TrainingRecorder`
（`methods/neural/recorder.py`，零 Qt 黑匣子）在训练循环里采集四类中间量，
经 `MLResult.artifacts` 契约化，UI 按 PageSpec 渲染五页：

| 页 | kind | 回答的问题 |
|---|---|---|
| 训练动态 | mpl | loss/val/lr/梯度范数/死 ReLU 五联曲线 |
| 权重热图 | nn_weights | 每层权重长什么样、训练前后如何变化 |
| 表示演化 | nn_replay | 类簇在第几个 epoch 分开（隐层→PCA 2D 回放） |
| 特征归因 | mpl | 哪些特征推高/压低预测（积分梯度，diag 开启时算） |
