 # ML Toolbox 使用指南
 
 ML Toolbox 用于把数据准备、预处理、算法运行、神经网络训练、实验比较和结果阅读组织成可复核的流程。软件保留运行身份、指标、诊断、曲线、日志、checkpoint 和产物引用；使用者通过 GUI、命令、MCP 或 AI 工具都能访问同一批事实。
 
 ## 1. 你能用它做什么
 
 - 从 CSV、表格、数组、合成规格或图数据建立数据集；
 - 自动或显式定义缺失值、编码、缩放和划分管道；
 - 浏览可用的回归、分类、聚类、异常检测、时序、流形和神经网络方法；
 - 单独运行一个方法，批量运行多个方法，或生成可排序比较表；
 - 使用自定义 Network 代码进行前向试跑、训练、观测和 checkpoint；
 - 查看运行摘要、训练曲线、资源占用、日志尾和结果引用；
 - 将长任务放入后台队列，查看、等待、取消和调整并发；
 - 读取图表、预测数组和模型文件等大结果。
 
 ## 2. 推荐工作流
 
 ### 2.1 先了解环境
 
 先调用 describe_methods，确认问题类型、参数、主指标、资源估算和可选依赖。再调用 describe_capabilities 或同等能力查询，确认 GPU、TensorBoard、HDF5、优化器和后台任务是否可用。
 
 不要凭记忆拼接方法名。方法名是注册表中的稳定标识，拼错时系统会返回可操作错误。
 
 ### 2.2 准备数据
 
 prepare_dataset 的核心输入是 source。常见形式：
 
 ~~~json
 {"kind":"csv","path":"data/train.csv"}
 ~~~
 
 ~~~json
 {"kind":"arrays","X":[[1,2],[2,3]],"y":[0,1]}
 ~~~
 
 ~~~json
 {"kind":"synthetic","task":"classification","n_samples":500,"n_features":8}
 ~~~
 
 可选参数：
 
 - name：显示名；
 - target：目标列；
 - time_col：时序列；
 - pipeline：步骤列表和 split；
 - graph：边列表或边文件；
 - payload：HDF5 或逐行数组；
 - target_kind：custom 表示由方法自己定义指标；
 - diag：保留预处理诊断。
 
 回执会给出 dataset_id、pipeline_id、数据摘要、划分策略和图/负载引用。保存这两个 id，后续运行优先显式传入 dataset_id。
 
 ### 2.3 运行方法
 
 run_method 的最小请求：
 
 ~~~json
 {"method":"linear_regression","dataset_id":"ds_..."}
 ~~~
 
 常用参数：
 
 - overrides：只覆盖本次运行；
 - seed：固定随机性；
 - device：auto、cpu 或 cuda:0；
 - resource_guard：声明内存、核数或显存预算；
 - persist：是否写入运行存档；
 - diag：保留诊断。
 
 结果包含 run_id、指标、耗时、警告和产物引用。预测数组、完整曲线和模型文件通过 result_ref 获取。
 
 ### 2.4 批量运行和比较
 
 run_method_batch 适合快速筛选；它按给定顺序运行方法，并隔离单个方法的失败。compare_methods 在相同数据、划分、seed 和资源条件下生成对比表，并返回主指标方向和 winner。
 
 比较时必须确认：
 
 - dataset_id 和 pipeline_id 相同；
 - 目标列和任务类型相同；
 - 指标方向一致；
 - seed、预算和早停条件可比；
 - 失败方法没有被当成零分；
 - 警告和资源消耗没有被忽略。
 
 ## 3. 自定义网络
 
 run_custom 接收 code 或 code_path，二者二选一。代码定义 Network 类，训练器负责数据、损失、优化器、观测和保存。
 
 建议顺序：
 
 1. 用 dry_run=true 检查真实批量的前向形状；
 2. 需要时设置 warmup_steps 检查反传、loss 和梯度；
 3. 再提交正式训练；
 4. 长训练设置 checkpoint_every；
 5. 用 read_job 观察进度和 logs_tail；
 6. 用 describe_training 读取曲线；
 7. 需要继续时传 resume_from。
 
 device=auto 会按环境选择设备；显式要求 cuda 而环境不可用时会报错。网络代码创建张量时使用训练上下文提供的 device，避免混合设备错误。
 
 ## 4. 后台任务
 
 适合后台运行的场景：
 
 - 神经网络训练；
 - 大数据集方法；
 - 多方法批量比较；
 - 优化器搜索；
 - 自定义网络和长时间 warmup。
 
 典型流程：
 
 ~~~text
 submit_run -> read_job(wait=none/terminal) -> describe_training
                               -> cancel_run（需要时）
 ~~~
 
 read_job 的关键字段：
 
 - state：框架任务状态；
 - queued：是否还在项目并发队列；
 - progress_latest：最新指标；
 - progress、epochs：有限尾部或显式 full；
 - logs_tail：服务端输出的最后几行；
 - run_id：任务尚未结束时也可能已经生成；
 - result_ref：终态产物；
 - timed_out：本次等待是否到达上限；
 - wait_note：人类可读调度说明。
 
 超时表示“这次等待结束但任务可能仍在运行”，不是训练失败。取消是协作式请求，最终状态以 read_job 为准。
 
 ## 5. 结果阅读
 
 ### 5.1 运行摘要
 
 describe_run 用于确认：
 
 - 数据集和管道身份；
 - 方法和完整参数；
 - seed、device、预算；
 - 状态和错误；
 - 指标、警告和诊断；
 - 产物引用；
 - 关联的 job_id 和 checkpoint。
 
 ### 5.2 训练曲线
 
 describe_training 适合读取 loss、val_loss、学习率、梯度和自定义指标。长曲线默认摘要，使用 tags、limit、compare 或 pick 缩小返回字段。只有在确实需要完整序列时才请求 full。
 
 ### 5.3 资源和日志
 
 资源字段用于解释耗时和失败原因，不能当成模型质量指标。logs_tail 只覆盖 Python 层捕获的输出；原生库输出应根据 started_at、finished_at 去对应终端或日志文件。
 
 ### 5.4 checkpoint
 
 checkpoint_detail 可以查看路径、步数、epoch、指标、设备、网络签名和保存时间。last.pt 表示最近一次保存，best.pt 按验证指标更新。恢复训练要保留原 checkpoint 引用，并记录新的运行身份。
 
 ## 6. 数据处理注意事项
 
 - 训练部分拟合预处理，不能用验证和测试数据拟合；
 - 同一比较表中不要混用不同 pipeline_id；
 - 目标列不可同时作为特征；
 - 时序任务保持时间顺序，避免随机打乱造成泄漏；
 - 图任务确认边索引和观测行一致；
 - 大型或变长负载放 payload，不要嵌入 JSON；
 - source 路径必须在允许的数据根目录；
 - 重复准备相同内容应得到稳定身份，便于复用缓存。
 
 ## 7. 常见错误
 
 ### 找不到方法
 
 先 describe_methods，再检查名称大小写和可选依赖。不要自行修改注册表文件来“临时”加入方法。
 
 ### 数据集引用失效
 
 确认 dataset_id 属于当前 ML 数据根，检查 prepare_dataset 回执中的完整 id 和状态。重启后优先查询已有数据集，不要用显示名代替身份。
 
 ### GPU 或内存不足
 
 先使用 estimate 或 resource_guard，减小 batch、维度、workers 或并发。显式 cuda 不会静默回落 CPU。后台队列只控制并发，不会减少单个任务的内存需求。
 
 ### 自定义网络形状错误
 
 先 dry_run，提供 batch_probes=[1,2,真实训练批大小]。需要检查 loss 或梯度时增加 warmup_steps。回执中的模块形状轨迹比直接反复正式训练更有效。
 
 ### 任务像是“静默结束”
 
 先 read_job(detail=full, logs=10)。区分 job 自身异常、命令返回 ok=false、任务被取消和结果引用读取失败。若已有 run_id，继续用 describe_run 查看已经写下的运行事实。
 
 ## 8. AI 使用约定
 
 AI 调用应遵循：
 
 1. 查询能力和数据身份；
 2. 用小规模或 dry_run 验证请求；
 3. 提交一个结构化命令；
 4. 保存 job_id/run_id；
 5. 轮询摘要，不要每次请求完整曲线；
 6. 根据指标、警告、资源和日志共同判断；
 7. 需要人判断时给出候选和依据，不把自动分数当成结论。
 
 reason 参数用于说明本次操作的意图，会进入操作审计；它不是算法参数。
 
 ## 9. 性能建议
 
 - 重用 dataset_id 和 pipeline_id，避免重复拟合；
 - 用 batch/compare 共享数据视图；
 - 长曲线只取尾部和关键 tags；
 - 使用后台任务避免阻塞交互线程；
 - 通过 set_job_limit 控制显存压力；
 - 让 checkpoint_every 与单步成本匹配；
 - 自定义网络先用真实 batch 做 dry_run；
 - 大结果通过 result_ref 读取，按需分块。
 
 ## 10. 用户可见的边界
 
 ML Toolbox 不替使用者选择科学问题、解释因果关系或保证泛化。指标依赖数据划分、随机种子、预算和预处理。一个 winner 只能说明在给定实验条件下的比较结果。
 
 任务取消可能在检查点之间延迟。后台任务和本地运行目录属于当前项目环境；更换数据根、删除运行目录或清理 checkpoint 会影响可复核性。
