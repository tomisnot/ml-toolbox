# 交接：给下一代开发者

> 读完这份大约 20 分钟。它讲**这个仓怎么运转、东西在哪、坑在哪**；
> 不讲"最近改了什么"（那看 `git log`），也不抄任何数字（计数会漂——要规模就照文中给的命令自己数）。

---

## 1. 一句话

`ml-toolbox` 是一台**机器学习方法试验台**：可被 import 的方法库 + PyQt5 桌面软件 +
一个"让 AI 替你调这些方法"的模式。它服务于**做实验的人**（准备数据集、跑方法、比方法、看指标、留存档），
也服务于**接 AI 的人**（把上面这些能力经 MCP 暴露给模型，并用只读面板监督它干了什么）。

它有一层特殊身份：它是「让 AI 接入软件」框架 **mecha** 的**接入项目**之一
（另两个是 Energy Level、Get Paper）——所以仓库里有一层 `ml_mecha/` 专门做"把本仓能力接到框架上"。
框架本体不在本仓：`D:\code-nosync\mecha`（只读参考；要改框架别在这里改）。

## 2. 最短上手

### 装

```powershell
# ① 依赖（必须在**仓根**执行：requirements.txt 里有相对路径的 -e ../mecha）
python -m pip install -r requirements.txt
python -m pip install -e ".[ai]"          # AI 模式额外需要（mcp / uvicorn / mecha）
```

版本口径与"为什么两步"写在 `docs/交付说明.md` §1–§2（那是安装的**唯一权威**，README 只指向它）。
⚠ AI 模式要的 `mecha` 在 `[ai]` extra 里是 **GitHub URL 依赖**（钉了 tag）；上游仓若尚未公开，
这一步会失败——那时用本机兄弟仓的可编辑安装（`requirements.txt` 末行那种）。

### 跑

```powershell
python launcher.py            # 看门人：弹窗选「本地 GUI 模式」/「AI 模式」；控制台可敲 gui / ai / quit
```

看到什么算成功：

* **GUI 模式**：出主窗口，左侧能选数据集、选方法、看指标与图。
* **AI 模式**：起 headless 权威 + 本地 MCP 工具服务 + dsh 界面；在 dsh 里用自然语言让 AI 调
  `describe_methods` / `prepare_dataset` / `run_method` 之类，点会话头「◈ 监控」能看只读面板。

### ⚠ 出厂是 **LOCKED**，AI 跑不动是**设计如此**

`ml_mecha/assembly.py:278` 的默认 `mode: Mode = Mode.LOCKED`——**出厂什么都不许写**，
必须由**人类侧**显式放闸（`switch_ai()` / `switch_human()`，见 `assembly.py:166`/`:170`）。
所以"AI 调 `run_method` 被拒"最常见的原因不是 bug，是**没放闸**。
放闸的逻辑与切换控制台在 `launcher.py` 与 `ml_mecha/assembly.py`。

## 3. 目录地图

**主干**（改这里最可能影响别人）：

| 路径 | 是什么 |
|---|---|
| `ml_toolbox/core/` | 数据/运行/契约/持久化的**内核**（不 import GUI） |
| `ml_toolbox/methods/` | 方法实现（按族组织）；注册进方法表 |
| `ml_toolbox/ui/` | PyQt5 界面（只 import 内核与方法的公开面） |
| `ml_toolbox/opt/` | 序贯优化/自动调参子框架（与主库并列的第二个域） |
| `ml_mecha/` | **框架适配层**：命令声明、工具面、监控端点、MCP 宿主、能力图 |
| `launcher.py` · `app.py` · `app_entry.py` | 三个入口：看门人 / GUI / headless 权威 |
| `dsh/` | dsh 插件（client+host 两半）与**共享面板资产副本** |
| `tests/` | 门禁（见第 7 节） |

**外围**（一般不用动）：`cases/`（夹具）、`benchmarks/`、`checks/`（离屏截图等工具）、
`docs/`（文档；`项目定位.md` 是宪法、`契约.md` 是接口契约、`pitfalls.md` 是踩坑表）。

## 4. 本仓的固定用语（每个一句人话）

* **权威（headless）**：AI 模式里真正持有"写权"的那个进程（`app_entry.py --authority`）；
  GUI/dsh 都只是它的脸。
* **模式（Mode）**：`LOCKED` / `AI` / `HUMAN`——**谁**有权写。出厂 `LOCKED`。
* **通道（side）**：一次调用"是谁发的"：`ai` 或 `human`。归因、写权、审计都按它算。
* **命令面 / 工具面 / 查询面**：同一批能力的**三种分派路**——
  命令面 = 受门禁管、留审计（`ml_mecha/commands.py` 声明）；
  工具面 = 模型能看见的 MCP 工具（`ml_mecha/tools.py`）；
  查询面 = 只读查询（`engine.query`，`ml_mecha/engine.py:317`）。三者可能表达同一件事（见第 6 节末）。
* **命令声明（declaration）**：一条命令的"参数/必填/副作用/档位"写在一处（`ml_mecha/commands.py`），
  再由 `ml_mecha/core_commands.py` **机械投影**成框架认识的 `CommandSpec`。
* **能力图（capability map）**：把"能力 × 谁提供 × 谁消费"机械派生出来的平表
  （`ml_mecha/capabilities.py`，入口 `ml_capability_map()`）；对不上账就**硬失败**（`CapabilityDrift`）。**先读这个文件。**
* **Gate**：框架的写权闸（`mecha.gate`）——所有域状态写入都经它，留痕也在那里。
* **History / 事件史**：只增不改的账本。事件有两种 `kind`：`state`（会被折进快照）与
  `history`（只记事，不进快照）。字段是 `op`（动作名）/ `target`（键）/ `after`（新值）/ `before`（前像）。
* **快照（snapshot）**：`{键名: 值}` 的当前域状态（如 `current.dataset_id`）；由事件史 fold 出来。
* **runs/ 存档**：磁盘上的实验真值（`runs/<run_id>/record.json`，跨重启可见）——
  与"事件史"是两件事：史讲"谁什么时候做了什么"，存档讲"那次实验的结果"。
* **端口文件**：权威把动态端口写在仓根（监控端口、MCP 端口）；面板/dsh 靠它找地址。
* **面板资产**：`dsh/src/dsh-panel/` 是从 mecha 仓**逐字复制**来的共享面板（见第 6 节，别就地改）。
* **null 垫片（R8-2）**：模型送显式 `null` 时"丢键还是原样传"的规则；由**声明**唯一决定。

## 5. 跟着一条数据流走一遍（**本节最值得花力气**）

场景：**AI 在 dsh 里让模型跑一次 `run_method`**。

```
① 模型 → MCP 工具调用 mcp__mltoolbox__run_method
      落地：ml_mecha/mcp_host.py::build_mcp_server        （把 ToolRegistry 注册成 MCP 工具）
② 工具本体 run_method
      落地：ml_mecha/tools.py                              （把模型参数翻成"命令 spec"）
③ 引擎入口 engine.run(spec)
      落地：ml_mecha/engine.py:498                         （统一失败归一化、事件写口）
④ 命令面 CommandRegistry.invoke（框架）
      声明：ml_mecha/commands.py  →  投影：ml_mecha/core_commands.py
      ⚠ 这里发生：Side/Scope 检查、写权闸（Gate）、审计事件 command.run_method
⑤ 命令处理 _cmd_run_method
      落地：ml_mecha/engine.py:649
      → _build_request（engine.py:961）：把 spec 变成 RunRequest（读 diag/seed/persist/resource_guard）
      → _execute_one：真正跑方法（ml_toolbox/methods/**）
⑥ 结果分两路
      · 域状态：经 Gate 写 current.*（快照 + state 事件）
      · 实验摘要：ml.run 事件（只记史）+ 大对象进工件仓（事件里只留 locator）
        落地：ml_mecha/assembly.py 的 _history_event_writer
⑦ 落库：runs/<run_id>/record.json
      落地：ml_toolbox/core/persistence.py
⑧ 只读出口：监控端点
      落地：ml_mecha/monitor_http.py
      路由：/status · /activity · /history · /config（框架四基础路由）
            + /summary · /runs（本仓附加路由，回 {rows: [...]}）
⑨ 人看见它：dsh 右栏面板（共享资产 dsh/src/dsh-panel/）
      飞行记录仪（事件史）/ 配置态（快照）/ 运行记录（/summary）/ 磁盘存档（/runs）
```

**另一条入口：GUI**（`python app.py`）走的是**另一条路**——
`ml_toolbox/ui/` → `ml_toolbox/api.py`（`Session`）→ `ml_toolbox/core/`，
**不经过命令面/Gate/事件史**。这一点很重要，见第 8 节。

## 6. 改代码前必须知道的坑

1. **LOCKED 会让你以为坏了**：出厂 `Mode.LOCKED`（`ml_mecha/assembly.py:278`），
   AI 写操作全被拒是**设计**。先放闸再看。
2. **"搜不到"≠"不存在"**：判断"这东西没有消费者"必须**跨调用链**看。
   真实教训：`run_method` 的 `diag` 在 handler 本体里搜不到，看起来是死参数；
   实际由它调用的 `_build_request`（`engine.py:961`）消费。**只扫一个函数体会得出反向结论。**
3. **新增/删除参数要补探针**：交付判据里有一张"逐参数走一遍 null 垫片"的探针表，
   参数集合变了它会红，并提示你补探针（在 `tests/test_ml_delivery.py` 里搜 `探针` / `_EXPECTED_OPTIONAL_PARAMS`）。
   这是**故意的**：它防的是"某类参数悄悄落在两个规则之外"。
4. **`dsh/src/dsh-panel/` 是逐字副本**：与 mecha 仓的共享资产必须**逐字一致**，
   有一道**常量指纹守卫**看着它（`dsh/test/panel-assets.test.ts`）。要改就**整份重新复制**并同步指纹，
   **别就地打补丁**（尤其别为了方便改它）。
5. **判据读的是"提交态的内容"，不是 git**：别用 `git show` 之类绕过；
   也别把注释/docstring 里的示例路径当成真引用。
6. **事件字段改过名**：现在是 `op`/`target`/`after`/`before`。
   按**事件名筛**时用 `op`（`command.*`、`ml.run` 都在 `op` 里）；
   域状态事件的 `target` 才是键名（`current.*`）。拿旧名 `key`/`value` 去读会安静地取不到。
7. **工具面与查询面可能是"同一能力的两条分派路"**：
   例如 `describe_*` 工具与 Surface 查询共用 `engine.query` 分派（`ml_mecha/tools.py` 与
   `ml_mecha/engine.py:317`）。**别把它当成重复实现去"合并"**——它们是两个面，各有消费者
   （今天仍是各写一份；是否上提为"声明一次、两面派生"记在第 8 节）。
8. **能力图对不上账 = 硬失败**：`ml_mecha/capabilities.py` 会 `raise CapabilityDrift`。
   你加了能力/改了消费者，却忘了同步声明面，它当场红——这是本仓最值钱的守卫之一，**别把它绕过去**。
9. **MCP 线上不声明 outputSchema**（是刻意的，见 `ml_mecha/mcp_host.py` 与
   `tests/test_ml_delivery.py` 里那条判据）；改返回结构别顺手加声明式输出结构。
10. **写状态只有一条路**：经 Gate（`make_state_writer`）。绕过它写 `current.*` 会破坏
    "快照能从史折出来"这条不变量。

## 7. 判定 / 门禁

| 命令 | 是什么 |
|---|---|
| `python tests/run_all.py` | **一键门**。分两阶段并行跑："重负载"（冒烟/回归/UI/优化）先跑完，再跑"时延敏感"（面板/适配器/能力图/交付链）。阶段划分见文件顶部说明 |
| `npm test`（在 `dsh/`） | 面板与 TS 侧判据（`node --test`）；它已由 `tests/test_dsh_panel.py` 挂进上面那道门 |
| `npm run typecheck`（在 `dsh/`） | 插件与共享面板的类型检查（消费者必须能过） |
| `npm run bundle`（在 `dsh/`） | 重建 dsh 插件产物；**改了 client 半就必须重建**（dsh 只吃产物） |

**"能红"的判据长什么样**（改坏了会当场响，不是摆设）——各举一例，看位置而不是抄结论：

* **能力图对账**：`tests/test_ml_capabilities.py`（声明与运行时对不上即红）
* **交付链契约**：`tests/test_ml_delivery.py`——含 MCP wire 形状、null 垫片探针、只读端点形状
* **适配器与命令面**：`tests/test_ml_mecha.py`
* **面板资产逐字一致 / 导入闭包零 `node:`**：`dsh/test/panel-assets.test.ts`、`dsh/test/panel-extra-pages.test.ts`
* **共享面板单测**：`dsh/src/dsh-panel/*.test.ts`（随资产逐字复制，**不要改**）

**写判据的风格**（本仓惯例）：既能红、又自证"扰动真的落上了"（否则就是哑守卫）；
不要断言时序（会 flaky），断言**契约**；计数类判据自带"请补探针"的提示语。

## 8. 已知问题 / 挂起项（含**故意**挂着的）

1. **GUI 不走 Gate/事件史**：GUI 那条路（`ml_toolbox/ui/` → `ml_toolbox/api.py`）**不产生审计**，
   也不进 `current.*` 快照。⇒ 别把"面板上没看到"当成"没发生过"。
   （挂起原因：先把 AI 模式那条链路做扎实；解法方向是让 GUI 也经命令面，属较大改造。）
2. **`describe_*` 工具 ↔ Surface 查询的"声明一次、两面派生"**：**故意不做**。
   它需要**框架侧缝扩展**（让投影同时生成查询条目），而今天只有本仓一家是消费者
   ⇒ 按"n=1 不预建"挂起。**触发条件**：第二个项目也要这条路时再上提。
3. **`mecha` 的 GitHub 仓未公开前，`[ai]` extra 装不上**：`pyproject.toml` 里 mecha 是 URL 依赖
   （钉了 tag）。建仓后即可用；本机开发走 `requirements.txt` 的可编辑安装。
4. **共享面板没在真实 dsh 实例里跑过**：本仓这一侧的证据到"离线渲染 + 共享单测 + 产物 bundle +
   MCP/命令面端到端"为止；面板在真实宿主里的样子（挂载容器、页签、两页数据）**未宣称**已验证。
5. **`cases/` 里有几个夹具当前无人引用**（历史遗留）：已脱敏，留着不影响；删不删是策展问题。
6. **`ml.mecha` 的账本/审计来自框架**：本仓只声明与消费；框架侧改动会波及本仓判据
   （遇到过"框架改了事件形状/前置闸顺序"这类事，处理原则：**改判据的期望，不改框架**）。

## 10. 这份文档的维护规矩

**必须更新它**（同一笔提交里改）当且仅当发生下列之一：

* 入口/启动方式变了（第 2 节）——例如新增入口、安装步骤口径变化；
* 主干目录或"改哪里"的分工变了（第 3 节）；
* **命令声明 / 工具面 / 查询面**的结构变了（第 4、6 节涉及的用语与坑）；
* 门禁的**跑法**变了（第 7 节）——新增/改名套件、行数结构变化；
* 挂起项**解掉或新增**（第 8 节，含触发条件变化）；

⚠ 别在本文档里**加计数**（方法数/用例数/文件数）——要规模就写命令让人自己数；
真要写数字，写"此刻实测"并注明日期与命令，且**别在别处重复**。

## 附：给 AI 代理的三条

1. **从哪道门进来**：要动这个仓的**数据或实验**，只走**工具面/命令面**
   （`ml_mecha/tools.py` → `engine.run`）；只读信息走**查询面**（`engine.query`）。
   **不要**直接改 `current.*`、不要绕过 Gate 写状态、不要自己 new 一个内部对象去改内存状态。
2. **不许做的事**：不改 `dsh/src/dsh-panel/`（逐字副本）；不改框架（mecha）；不新建"检查/判据"除非被要求；
   不把 GUI 与 AI 模式**同时**起在同一个数据根（写租约只允许一个写宿主）；不手抄计数进文档。
3. **本仓最容易被 AI 违反的纪律**：
   ① **"搜不到"就下"没有消费者"的结论**——必须跨调用链（真实教训：`diag`）；
   ② **判据红了先改判据**——先判"是实现错还是期望过时"，**别把它改松**；
   ③ **在错误的作用域里取证**——先跑一次拿真实结果，再下结论；报"不存在"前写清查的是哪个范围。
