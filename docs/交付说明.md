# ML Toolbox 交付说明（客户向）

这份文档面向**使用者**：怎么装、怎么启动、两种模式各能做什么、出问题先看哪里。
术语尽量少；需要细节时按文中的路径去看对应文件。

> 相关技术文档（开发者向，可先不看）：
> `docs/mecha/07-交付形态-双模式与dsh桥.md`（交付形态设计）、
> `dsh/README.md`（面板插件与 R1 观测程序）。

## 1. 前置条件

### 1.1 必需

| 组件 | 版本 | 检查命令 | 说明 |
|---|---|---|---|
| Python | 3.10（实测） | `python -V` | 运行本体 |
| Python 依赖 | 见 `requirements.txt` | `pip install -r requirements.txt` | numpy / pandas / scipy / scikit-learn / xgboost / lightgbm / statsmodels / umap-learn / PyQt5 / pyqtgraph / matplotlib |
| **mecha 框架** | 0.2.0 | `python -c "import mecha; print(mecha.__version__)"` | **AI 模式必需**：ML 的 headless 权威层（`ml_mecha`）架在它上面 |
| **MCP SDK** | 2.x（实测 2.2.0） | `python -c "import mcp"` | AI 模式必需：ML 用它在本地起工具服务 |

安装 mecha（**editable**，两个仓各自独立演进，不 vendor）：

```powershell
pip install -e D:\code-nosync\mecha
```

### 1.2 AI 模式额外需要（本地 GUI 模式不需要）

| 组件 | 版本 | 检查命令 | 说明 |
|---|---|---|---|
| Node.js | 18+（实测 v24） | `node -v` | 构建监控面板插件（一次性） |
| npm | 随 Node | `npm -v` | 同上 |
| **dsh** | 0.1.7-rc.1（实测） | `dsh --version` | AI 界面本体；不在 PATH 时 AI 模式仍能跑，只是没有界面 |

### 1.3 可选

- **torch**：装了才有 `torch_mlp` 神经网络方法（不装时其余 50+ 方法照常）。
- **optuna**：装了才有 TPE/ASHA 等优化引擎（不装时自研引擎照常）。

> 未装可选依赖时**不会报错**，对应方法/引擎不出现在列表里而已。

## 2. 一次性准备

```powershell
# ① 装 Python 依赖
pip install -r requirements.txt
pip install mcp
pip install -e D:\code-nosync\mecha      # 若还没装

# ② 面板插件（AI 模式的右栏监控面板）——**通常不用手动做**
#    launcher 首次进 AI 模式时会自动 npm install + npm run bundle；
#    想提前装好也可以：
cd dsh
npm install
npm run bundle
cd ..
```

**关于面板插件**：`dsh/lib/` 是构建产物、**不入库**（提交构建产物会静默漂移：改了源码忘了重建，没人会发现）。所以由 `launcher.py` 自动兜：`node_modules` 缺失就装、产物缺失或比 `dsh/src/` 旧就重建、构建失败就**明确告诉你**并跳过面板（AI 模式与工具照常可用）。

## 3. 怎么启动

**最省事**：双击项目根目录里的 `启动 ML Toolbox.bat`。

等价的手动方式：

```powershell
python launcher.py
```

会弹一个窗口问"这次怎么用"，两个按钮：

| 选择 | 发生什么 | 写权 |
|---|---|---|
| **本地 GUI 模式** | 打开熟悉的完整界面（等同于 `python app.py`） | 在你手上；AI 完全看不见这台软件 |
| **AI 模式** | 后台起计算权威（无窗口），前台打开 AI 界面（dsh） | 交给 AI；你在对话里指挥，右栏只读监控看它每笔操作 |

命令行直达（跳过弹窗）：

```powershell
python app_entry.py --gui           # 本地 GUI 模式
python app_entry.py --authority     # 只起后台权威（AI 模式的一半；界面自己起）
```

### 3.1 两种模式各能做什么

| 能力 | 本地 GUI 模式 | AI 模式 |
|---|---|---|
| 手动选方法、调参、看图 | ✅ | ❌（AI 模式下不开 GUI，见下） |
| AI 用自然语言驱动 ML 工具 | ❌ | ✅ |
| 右栏只读监控（谁改了什么 / 跑过什么） | ❌ | ✅ |
| 实验记录 `runs/` | ✅ | ✅（两者共用同一份） |
| 本地 CSV 数据 | ✅ | 需显式授权 `--dataset-roots`（见 §6.3） |

> **为什么 AI 模式不开 GUI**：计算权威与界面必须是**单一写者**。ML 的 Qt 界面目前不经过权限门（它直接调运行器并自己存盘），把它和 AI 权威一起拉起来会出现两份真值；而且训练库（lightgbm/torch）与 Qt 的 native 初始化顺序很敏感，多一个 Qt 事件循环会平白多一类崩溃。要看图就切回本地 GUI 模式。

### 3.2 怎么切换模式

三种方式，任选：

1. **在启动程序的黑色控制台窗口里输入** `gui` 或 `ai`，回车；
2. 本地 GUI 模式里：菜单「切换至 AI 模式」；
3. 写一个文件：在项目根建 `.mode-request`，内容写 `gui` 或 `ai`。

切换时程序会**先等当前模式的进程真正退出**（把账本写租约交还）再起新模式，所以不会出现"两边同时写"。跑过的实验记录都在 `runs/`，不断档。

### 3.3 怎么退出

- 关掉当前模式的窗口；或
- 在控制台输入 `quit`；或
- 控制台按 `Ctrl+C`。

## 4. AI 模式示例对话

在 AI 界面里**说人话**即可，不用记工具名。AI 侧的工具名形如
`mcp__mltoolbox__describe_methods`（界面里通常只显示方法名）。

### 4.1 一段完整对话

> **你**：现在有哪些方法能用？按族帮我看看。
>
> **AI**：（调 `describe_methods`）一共 59 个方法，覆盖 linear / tree / svm / cluster /
> neural 等族……（列出名字与任务类型）
>
> **你**：用这份 CSV 建个数据集，目标列是 `label`。
>
> **AI**：（调 `prepare_dataset`）已建好：`dataset_id = ds-001-...`，
> 120 行 4 列，预处理链指纹 `edfc8b095af5`。
>
> **你**：跑一下 logistic，然后跟 svc 比比。
>
> **AI**：（调 `run_method` → `compare_methods`）logistic 的 f1 = 0.966
> （`run_id = logistic-5635347-42`）；svc f1 = 0.93。logistic 更好。
>
> **你**：lightgbm 数据量大，可能要跑很久，别卡住。
>
> **AI**：（调 `submit_run` 提交后台任务）已提交，任务号 `job-1`，我隔一会儿查一次。
> （稍后调 `read_job`）跑完了：`run_id = lightgbm-1106012-42`，accuracy = 0.94。

### 4.2 真实回执形状（AI 看到的就是这些）

```jsonc
// describe_methods
{"ok": true, "method_count": 59,
 "methods": [{"name": "logistic", "family": "linear", "task": "classification",
              "target_kind": "categorical", "purposes": ["baseline"], "supports_predict": true}, ...],
 "error": ""}

// prepare_dataset
{"ok": true, "dataset_id": "ds-001-synthetic-classification",
 "pipeline_id": "edfc8b095af5", "n_rows": 120, "n_features": 4,
 "target": "target", "warnings": []}

// run_method（大产物不内联：只给 run_id 与指标）
{"ok": true, "run_id": "logistic-5635347-42", "method": "logistic",
 "primary_metric": "f1",
 "metrics": {"accuracy": 0.9667, "precision": 0.9333, "recall": 1.0,
             "f1": 0.9655, "auc": 0.9955},
 "elapsed_s": 0.03, "warnings": []}

// submit_run（长任务：立刻返回，不阻塞）
{"ok": true, "job_id": "job-1", "command": "run_method",
 "cancel_supported": true, "state": "running"}

// read_job（轮询到终态；result_ref 里有运行编号）
{"ok": true, "job_id": "job-1", "state": "done", "cancel_supported": true,
 "progress": [], "progress_latest": {},
 "result_ref": {"kind": "ml_command", "command": "run_method",
                "run_ids": ["logistic-5635347-42"]},
 "error": "", "ref_error": ""}

// 失败也是结构化的（AI 能按 kind 决定怎么改，不用猜）
{"ok": false, "error": {"message": "写权处于 LOCKED，任何通道都不能改域状态",
                        "info": {"kind": "authority_locked",
                                 "hint": "先由人类侧切到目标模式", "suggest": "..."}}}
```

### 4.3 AI 能用的工具清单（11 个）

| 工具 | 干什么 | 大结果怎么给 |
|---|---|---|
| `describe_methods` | 列可用方法 | 只给名字/族/任务 |
| `describe_method` | 某方法的可调参数 | 参数表 |
| `describe_dataset` | 已准备数据的规模/指纹 | 摘要，不内联数据 |
| `describe_run` | 按 `run_id` 回看某次运行 | 指标 + **产物类别名**，不内联数组 |
| `prepare_dataset` | 登记数据 + 拟合预处理链 | `dataset_id` |
| `run_method` | 跑一个方法（同步） | **`run_id`** + 指标 |
| `run_method_batch` | 顺序跑多个方法 | 每个方法的 `run_id` + 逐项失败原因 |
| `compare_methods` | 多方法对比 | 对比表 + 最优 |
| `submit_run` | 把一次运行**提交为后台任务** | `job_id` |
| `read_job` | 查任务进度/结果 | 状态 + `result_ref` |
| `cancel_run` | 请求取消任务 | 明确回"已请求"（不谎报"已取消"） |

> **长任务**：单次调用有 10 分钟上限（启动时自动配置）。更久的用 `submit_run` +
> `read_job`，AI 不会被卡住。取消是**协作式**的：任务会在下一个检查点停下，
> 单次训练计算中途不可打断（这一点如实告知，不假装能打断）。

## 5. 驾驶舱（只读监控）

AI 模式下，AI 界面会话头部有一个 **「◈ 监控」** 按钮：点它会在右侧栏打开监控面板
（也可以在右栏标签里找到「ML 监控」）。面板**只读**——它不能改任何东西。

### 5.1 三页各看什么

| 页签 | 看什么 |
|---|---|
| **飞行记录仪** | "谁在什么时候改了什么"：每条写事件一行（`#序号 / 谁 / 类型 / 原因`），展开看 `before → after` 全量 |
| **配置态** | 当前状态快照的现值 + 每键最后写入的归因（谁、第几条） |
| **运行记录** | 最近跑过什么：操作史里的运行（AI 跑过就一定有）+ 磁盘存档 `runs/`（跨重启可见） |

> "运行记录"里两个来源为什么可能不一样：磁盘存档只在**显式要求保存**时才写
> （AI 默认不落盘）。所以**存档为空不等于没跑过**——面板上写了这句提示。

### 5.2 `mode` 徽标的三种含义

面板右上角一直显示当前写权在谁手上：

| 徽标 | 含义 |
|---|---|
| **写权 AI**（紫） | AI 模式：只有 AI 通道能写 |
| **写权在人**（绿） | 本地 GUI 模式：只有人（界面）能写 |
| **全员禁写**（黄） | 维护态：谁都不能写 |
| **权威离线**（红） | 连不上后台权威（软件没在 AI 模式跑？或刚被切走） |

### 5.3 地址从哪来（为什么不用你配）

监控端口每次启动由系统分配，程序会把它写进项目根的运行期文件
（`.ml-monitor-port` 与 `.ml-mecha-runtime.json`）。面板**不问 AI、也不猜端口**：
它去问 dsh 自己的一个同源只读地址（`/ml-toolbox/monitor-url`），由插件读上面那个
运行期文件后回一个地址。读不到就显示"监控端点未知 + 重试"，**不会**回落到某个
"常见端口"（那等于把面板悄悄指向别人的服务）。

> 改了面板源码后要 **`cd dsh && npm run bundle` 并重启 AI 界面**（dsh 不热加载面板）。

## 6. 故障排查

### 6.1 启动相关

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报 `writer_lease_held` / "数据目录已被另一个写宿主占用" | 已经有一个实例在跑（或上次没退干净） | 关掉所有 ML Toolbox 窗口与控制台，确认真没有残留 `python` 进程后再启动。同一数据目录**同时只允许一个写者**（这是账本序号不重复的前提） |
| 报"已经有一个看门人在跑（pid=…）" | 同上，看门人级别 | 先关掉那个实例。若确认它已经是死进程，**直接重跑即可**（陈旧锁会自动接管） |
| `ModuleNotFoundError: No module named 'mecha'` | mecha 框架不在位 | `pip install -e <mecha 仓路径>`；或设环境变量 `MECHA_ROOT` 指向它 |
| `ModuleNotFoundError: No module named 'mcp'` | 缺 MCP SDK | `pip install mcp` |
| 界面报 `lightgbm`/OpenMP 相关崩溃 | 导入顺序被破坏（训练库必须先于 Qt） | 别自己拼启动脚本；用 `python launcher.py` 或 `python app_entry.py --gui` |
| 模式弹窗起不来 | 无图形环境 / Qt 装不上 | 绕过弹窗：`python app_entry.py --gui` 或 `--authority` |

### 6.2 AI 模式相关

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 日志说 "PATH 里没找到 dsh" | 没装 dsh 或不在 PATH | AI 模式仍可用（工具在、AI 只是没界面）。装 dsh 后重跑；或按日志里给的命令手动起 |
| 日志说"面板插件未构建/构建失败" | 没 Node.js，或 npm 装/构建失败 | 按日志提示装 Node.js，或手动 `cd dsh && npm install && npm run bundle`。AI 模式与工具**照常可用**，只是没有右栏面板 |
| 日志说"权威未就绪：端口文件还是上一次的旧值" | 上一次被强杀留下了陈旧端口文件 | 程序会自己等**新**端口（不会连死端口）并超时报错。重跑一次通常就好；持续如此看权威自己的日志 |
| 日志说"权威未就绪：端口 N 上还没有 HTTP 响应" | 权威起了但服务没 listen（端口被占/依赖缺失） | 看权威进程的输出（同控制台）。它自己的报错会说明原因 |
| 面板**空白**或一直"正在解析监控端点地址…" | ① 不在 AI 模式；② 权威刚被切走；③ host 半没挂上 | 确认是 AI 模式；点面板里的**重试**；再看 `dsh/README.md` 的排查。面板**不会**回落到默认端口（那会指向别人的服务） |
| 面板显示"监控端点未知：命令未返回监控地址" | **旧版面板的已知 bug**（地址经命令取、返回值形状读错） | **已修**：地址改走同源只读路由。**必须重建面板并重启 AI 界面**才生效：`cd dsh && npm run bundle`，再重跑 `python launcher.py`（dsh 不会热加载面板） |
| 面板拿到的是**上一次**会话的端口（一打开就"权威离线"） | 旧版按启动目录找运行期文件，可能读到**残留**描述符 | **已修**：看门人现在显式把数据根经 `MLTB_ML_ROOT` 告诉面板插件。重跑 `python launcher.py` 即可；手工起 dsh 时请自己设 `MLTB_ML_ROOT=<ML 仓根>` |
| 面板显示"权威离线"（红徽标） | 连不上后台权威 | 软件可能已经切回 GUI 模式，或权威崩了。切到 AI 模式重试 |
| AI 调用工具报**超时** | 单次调用超过 10 分钟 | 让 AI 改用 `submit_run` + `read_job`（提交后台任务） |
| AI 调用工具报"连不上" | 权威中途崩了/重启过（端口变了） | 重跑 `python launcher.py`（权威与 AI 界面同生命周期）。这是已知限制，见 §7 |

### 6.3 数据与权限

| 现象 | 原因 | 怎么办 |
|---|---|---|
| AI 读 CSV 报 `dataset_roots_required` | 没授权任何数据目录（**默认拒绝**，这是有意的） | 启动时显式授权：`python app_entry.py --authority --dataset-roots <目录>`（可重复）。不授权时合成数据/数组/内存表仍可用 |
| AI 读 CSV 报 `dataset_path_denied` | 路径在授权目录之外 | 用授权目录里的路径，或加授权 |
| AI 说写不进去 / `authority_locked` | 写权还在 LOCKED（刚起、闸没开完） | 等几秒重试；正常路径不该出现（选 AI 模式即授权 AI 写） |
| 找不到跑过的实验 | 磁盘存档只保存**成功且被要求保存**的运行 | 看驾驶舱「运行记录」页的"操作史"部分（AI 跑过就有）；或在 GUI 模式看历史面板 |

## 7. 已知限制（如实告知）

1. **权威重启后 AI 界面里的工具可能"在但用不了"**：这是 dsh 内置 MCP 客户端在
   streamable-http 上的已知未决行为。当前靠"权威与 AI 界面同生命周期"规避——
   出现时**重跑 `python launcher.py`** 即可。若频繁遇到，见下面 §7.1 的观测程序
   （它决定要不要上更重的自愈方案）。
2. **取消是协作式的**：任务在检查点停下，单次训练计算中途不可打断。
3. **任务编号（`job_id`）不跨模式**：切换模式会终止后台任务；跨模式/跨重启回看运行
   请用磁盘 `runs/`（或驾驶舱「运行记录」）。
4. **AI 模式下看不到图**：面板只给指标与元数据。要看图切回本地 GUI 模式
   （数据都在 `runs/<run_id>/`，历史面板能打开）。
5. **失败/取消的运行在 GUI 批量路径不落盘**：属既有行为；成功运行都在 `runs/`。

### 7.1 R1 手动观测程序（判断是否需要更强的自愈方案）

**为什么观测**：dsh 官方文档自己列了一条限制——HTTP 连接建立后，请求失败走 SDK 的
恢复机制而不是重建连接；"Streamable HTTP 的重连归属仍未决定"。所以要确认它**到底
会不会咬人**。

**步骤（约 3 分钟）**

1. `python launcher.py` → 选「AI 模式」。
2. 在 AI 界面里调一个只读工具（例如问"现在有哪些方法能用？"）→ 确认能拿到结果。
   记下项目根 `.ml-mecha-runtime.json` 里的 `mcp_port`（记作 **P1**）。
3. **在 AI 界面不退出的前提下**杀掉后台权威：
   `Get-Process python | Where-Object { $_.Id -eq <authority_pid> } | Stop-Process -Force`
   （`authority_pid` 见同一个文件）。
4. 重新起一台权威（同一目录）：`python app_entry.py --authority`
   → 它会拿到**新端口**（记作 **P2**，与 P1 不同）。
5. **不要重启 AI 界面**。回到会话里再调同一个只读工具。

**看结果**

| 看到什么 | 含义 | 该做什么 |
|---|---|---|
| 调用**成功** | 客户端已恢复 | 不用管，保持现状 |
| 工具**还在列表里但每次调用都失败**，**重启 AI 界面后立刻恢复** | **命中了那条死区** | 告诉开发者：该上自愈方案了（技术文档 §4 P3） |
| 工具**从列表里消失** | 重连次数耗尽后工具被移除 | 重启 AI 界面即可；记进排错表 |
| AI 界面自己崩了 | 与这条无关 | 看控制台输出 |

> 想少花时间也可以只做第 3 步（不重启权威）——但那时"工具在但用不了"是**正常**的
> （服务真的没了）。要区分"服务没了"和"死区"，**必须**做完第 4 步。

## 8. 文件放哪了
