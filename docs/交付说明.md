> `mecha @ git+https://github.com/tomisnot/mecha@v0.2.0`（上游 `v0.2.0` 已发布、
> 历史已定稿 ⇒ tag 不会漂）。⚠ **该仓目前尚未公开（404）⇒ 上游仓建好后该 URL 才可解析**。
> 本机开发走下面这条**可编辑安装**（两个仓各自独立演进，不 vendor）——**同一事实、两种场合**：
> 公开安装用 URL + tag，本机开发用可编辑安装。

本机开发安装 mecha（**editable**，与 `requirements.txt` 末行同源）：

```powershell

```

## 2. 一次性准备

```powershell
# ① 装 Python 依赖 —— **本机开发：两步都要跑**（这条是安装步骤的唯一权威处；
#    README 只指向这里，不各写一份）
#    ⚠ 必须在**仓根**执行：requirements.txt 里的 `-e ../mecha` 是相对路径，
#      解析基准是 CWD（不是 requirements.txt 所在目录）。
#    ⚠ 非本机环境**只需一步**：`pip install -e ".[ai]"`（mecha 由 `ai` extra 的
#      GitHub URL 依赖带进来；⚠ 该仓尚未公开时这一步会失败，见 §1.1 的说明）。
cd <本仓根目录>
python -m pip install -r requirements.txt   # GUI 全量 + mecha（requirements.txt 末行 `-e ../mecha`）
python -m pip install -e ".[ai]"            # + mcp / uvicorn（pyproject.toml 的 `ai` extra）

# ② 面板插件（AI 模式的右栏监控面板）——**通常不用手动做**
#    launcher 首次进 AI 模式时会自动 npm install + npm run bundle；
#    想提前装好也可以：
cd dsh
npm install
npm run bundle
cd ..
```

> **为什么是两步、为什么 mecha 在 requirements.txt 而不在 pyproject.toml**：
> `mecha` 是本机**兄弟仓**的可编辑安装（不是 PyPI 包）——写进 pyproject 只能写死
> `file://` 路径，换机器/盘符即失效，等于把"未声明"换成"路径失效"。所以它按
> requirements.txt 的相对 `-e`（与 EL 同款）；而 `mcp`/`uvicorn` 是本机可解析的普通
> 依赖，声明在 pyproject 的 `[project.optional-dependencies].ai`（**一个事实一个家**，
> 不在 requirements.txt 再列一遍）。

**关于面板插件**：`dsh/lib/` 是构建产物、**不入库**（提交构建产物会静默漂移：改了源码忘了重建，没人会发现）。所以由 `launcher.py` 自动兜：`node_modules` 缺失就装、产物缺失或比 `dsh/src/` 旧就重建、构建失败就**明确告诉你**并跳过面板（AI 模式与工具照常可用）。

## 3. 怎么启动

**最省事**：双击项目根目录里的 `启动 ML Toolbox.bat`。

等价的手动方式：

```powershell
python launcher.py
```

会弹一个窗口问"这次怎么用"，两个按钮：

| 选择 | 发生什么 | 写权 |
|---|---|---|
| **本地 GUI 模式** | 打开熟悉的完整界面（等同于 `python app.py`） | 在你手上；AI 完全看不见这台软件 |
| **AI 模式** | 后台起计算权威（无窗口），前台打开 AI 界面（dsh） | 交给 AI；你在对话里指挥，右栏只读监控看它每笔操作 |

命令行直达（跳过弹窗）：

```powershell
python app_entry.py --gui           # 本地 GUI 模式
python app_entry.py --authority     # 只起后台权威（AI 模式的一半；界面自己起）
```

### 3.1 两种模式各能做什么

| 能力 | 本地 GUI 模式 | AI 模式 |
|---|---|---|
| 手动选方法、调参、看图 | ✅ | ❌（AI 模式下不开 GUI，见下） |
| AI 用自然语言驱动 ML 工具 | ❌ | ✅ |
| 右栏只读监控（谁改了什么 / 跑过什么） | ❌ | ✅ |
| 实验记录 `runs/` | ✅ | ✅（两者共用同一份） |
| 本地 CSV 数据 | ✅ | 需显式授权 `--dataset-roots`（见 §6.3） |

> **为什么 AI 模式不开 GUI**：计算权威与界面必须是**单一写者**。ML 的 Qt 界面目前不经过权限门（它直接调运行器并自己存盘），把它和 AI 权威一起拉起来会出现两份真值；而且训练库（lightgbm/torch）与 Qt 的 native 初始化顺序很敏感，多一个 Qt 事件循环会平白多一类崩溃。要看图就切回本地 GUI 模式。

### 3.2 怎么切换模式

三种方式，任选：

1. **在启动程序的黑色控制台窗口里输入** `gui` 或 `ai`，回车；
2. 本地 GUI 模式里：菜单「切换至 AI 模式」；
3. 写一个文件：在项目根建 `.mode-request`，内容写 `gui` 或 `ai`。

切换时程序会**先等当前模式的进程真正退出**（把账本写租约交还）再起新模式，所以不会出现"两边同时写"。跑过的实验记录都在 `runs/`，不断档。

### 3.3 怎么退出

- 关掉当前模式的窗口；或
- 在控制台输入 `quit`；或
- 控制台按 `Ctrl+C`。

## 4. AI 模式示例对话

在 AI 界面里**说人话**即可，不用记工具名。AI 侧的工具名形如
`mcp__mltoolbox__describe_methods`（界面里通常只显示方法名）。

### 4.1 一段完整对话

> **你**：现在有哪些方法能用？按族帮我看看。
>
> **AI**：（调 `describe_methods`）一共 59 个方法，覆盖 linear / tree / svm / cluster /
> neural 等族……（列出名字与任务类型）
>
> **你**：用这份 CSV 建个数据集，目标列是 `label`。
>
> **AI**：（调 `prepare_dataset`）已建好：`dataset_id = ds-001-...`，
> 120 行 4 列，预处理链指纹 `edfc8b095af5`。
>
> **你**：跑一下 logistic，然后跟 svc 比比。
>
> **AI**：（调 `run_method` → `compare_methods`）logistic 的 f1 = 0.966
> （`run_id = logistic-5635347-42`）；svc f1 = 0.93。logistic 更好。
>
> **你**：lightgbm 数据量大，可能要跑很久，别卡住。
>
> **AI**：（调 `submit_run` 提交后台任务）已提交，任务号 `job-1`，我隔一会儿查一次。
> （稍后调 `read_job`）跑完了：`run_id = lightgbm-1106012-42`，accuracy = 0.94。

### 4.3 AI 能用的工具清单（19 个）

> **AI 还有一份"说明书"（skill）**：`skills/ml-toolbox/SKILL.md`。它在 AI 模式启动时
> 被自动加载，内容 = 正典工作流 + 长训练姿势 + 写权/失败纪律 + 图任务 + 逐行负载
> + **已知边界**。工具清单那张表与**真实注册表逐名对账**
> （`tests/test_skill_surface.py`），所以**改工具面必须同时改它**——否则门禁会红并
> 指名道姓说少了哪个。首次克隆后若 AI 看不到这份说明书，跑一次
> `python checks/link_skills.py`。

| 工具 | 干什么 | 大结果怎么给 |
|---|---|---|
| `describe_methods` | 列可用方法 | 只给名字/族/任务 |
| `describe_method` | 某方法的可调参数 | 参数表 |
| `describe_dataset` | 已准备数据的规模/指纹/**预处理链逐步参数**/**实际划分口径**/**负载的形状与 dtype** | 摘要，不内联数据 |
| **`prepare_dataset`** | 登记数据 + 拟合预处理链；**可给 `pipeline` 声明自己组装这条链**（选内置步骤/换顺序/写自定义步骤/**分组留出**），**可给 `payload` 声明逐行负载**（变长/复数的大数组） | `dataset_id` + 链摘要 + 划分口径 + 负载形状 |
| `describe_run` | 按 `run_id` 回看某次运行 | 指标 + **产物类别名**，不内联数组 |
| `describe_training` | **训练过程观测**：逐 epoch 的 loss/val_loss/grad_norm/lr/dead_relu + 逐层梯度 + **方法自己上报的自定义 tag** | 默认只给**最新一轮**；`include_series=true` 才给整条序列（可用 `pick` 只取关心的几条） |
| **`run_custom`** | **跑一段自定义网络代码**（AI 写结构，系统管训练与观测）；可给 `device` | **`run_id`** + 指标 |
| **`describe_networks`** | 列出自定义网络（名字/指标/行数/用过几次） | 清单，不含源码 |
| **`describe_network`** | 按名字取回网络**源码**（改一版再跑，免重贴） | 源码 + 来源 `run_id` |
| **`checkpoint_detail`** | 某次运行的**模型存档**在不在、多少张量/参数、**含不含偏置**、在哪块设备上训的 | **权重不内联**；要用模型走 `eval_custom` |
| **`eval_custom`** | **装载模型，交给调用方的代码**去评估（采样/算能量/换尺寸外推） | 它上报的指标 |
| `run_method` | 跑一个方法（同步） | **`run_id`** + 指标 |
| `run_method_batch` | 顺序跑多个方法 | 每个方法的 `run_id` + 逐项失败原因 |
| `compare_methods` | 多方法对比 | 对比表 + 最优 |
| `submit_run` | 把一次运行**提交为后台任务** —— **长训练就走这条**：给 `method` 跑内置方法，给 `code` 跑自定义网络 | `job_id` |
| `read_job` | 查任务进度/结果 | 状态 + **逐代数值**（loss/val_loss，够判断早停）+ **中途就能拿到的 `run_id`** + `result_ref` |
| `cancel_run` | 请求取消任务 | 明确回"已请求"（不谎报"已取消"） |
| **`run_queries`** | **一次往返跑一串只读查询**（列方法→看参数→查数据集→看训练）；某步失败就停在**那一步** | 每步自带 `output` + 短摘要；失败步给教学原因 |
| **`clear_current_state`** | 把配置台面清零、回到默认（要在干净台面上开始时先调） | 逐键 `before`/`readback`，省掉一次复核往返 |

> **长训练怎么跑（这是唯一可行的形态）**：LLM 的一次工具调用本质是 HTTP 请求，
> 客户端**必须有超时**（本实例 10 分钟）⇒ "同步等训练跑完"对长训练天生不成立。
> ⇒ 正确姿势是**发一个开始信号就走**，之后自己轮询：
>
> ```
> submit_run(method=... 或 code=...)  → job_id          # 发完就走，不等
> read_job(job_id)                     → state + 逐代 loss/val_loss
>                                        + run_id（**训练中途就有**）
> describe_training(run_id)            → 想去查哪一代、哪个指标都行
> cancel_run(job_id)                   → 在 epoch 边界停下
> ```
>
> - **为什么轮询就够**：MCP 没有"服务端主动推给模型"这条路 ⇒ **只能 AI 主动查**；
>   而查询面是按"想查啥查啥"设计的（`describe_training` 给全部 tag 与整条序列）。
> - **`run_id` 为什么中途就有**：`result_ref` 只在终态产生，所以进度里单独带了
>   它 —— 否则"边跑边查曲线"根本没法开始。
> - **后台任务默认落盘**：跑完自动写 `runs/<run_id>/record.json`（**不用传 persist**）。
>   因为 job 状态只在进程内存里，权威一重启 `job_id` 就没了 —— 自动落盘保证
>   结果不依赖"进程活到你去取"。
> - ⚠ **取消是协作式的**：今天在**命令入口**、**方法与方法之间**、
>   以及**训练器的 epoch 边界**生效 ⇒ 一次 epoch 内部不可打断（如实告知）。

> **`describe_run` 与 `describe_training` 的分工**（别混）：
> 前者是**这次运行的元数据与最终指标**（读本会话内存），后者是**过程数值**
> （读磁盘事件文件）。⇒ 后者对"未落盘"（`persist=false`，AI 默认）与
> "跨重启的历史运行"同样有效——这两件事前者都做不到。

> **`describe_training` 读不到时不会假装**：训练时若没装 `tensorboard`，
> 事件文件根本不产生 ⇒ 它如实回 `available=false` + 可读原因，
> **不是**"跑到第 0 个 epoch"。

### 4.4 自定义网络：AI 写结构，系统管训练（自由度在这里）

`torch_mlp` 的旋钮再多，**拓扑**也是写死的（`nn.Sequential` ⇒ 只能是线性链）
⇒ 想组**残差网络**、多分支、自己定损失或前向，得让 AI 直接写代码。
`run_custom` 就是那条路，代码只需要：

```python
class Network:
    def build(self, n_in, n_out, *, nn):     # 必需：返回 nn.Module（任意拓扑）
        return nn.Sequential(nn.Linear(n_in, 16), nn.ReLU(), nn.Linear(16, n_out))
    # 可选：loss(*, nn, n_out) / configure(model, *, torch, lr, weight_decay)
    #       / forward_step(model, batch, ctx)
```

**为什么这条路不牺牲观测**：训练循环/进度/TensorBoard/逐 epoch 观测/指标/存档/
五页检视**全部由系统代管**（它跑的就是一台方法）⇒ 残差网络照样能
`describe_training` 读曲线、照样在 GUI 里看权重热图与表示演化。

**⚠ 三条要记住的**：
1. **代码只写结构**：不许自己写盘、不许碰 GUI——观测由系统统一负责
   （所以"AI 写的代码"与"AI 调 `run_method`"在记账上是同一类）；
2. **代码会跟着运行进存档**（`runs/<id>/record.json`）⇒ 跨重启能取回；
   `describe_networks` / `describe_network` 就是给这个用的
   ——**改超参别重贴代码**；
3. **`run_custom` 的训练超参走 `overrides`**（epochs/batch/lr/val_split/
   latent_every/grad_clip/early_stop…），**结构参数写进代码**——两边不要串。

> **`submit_run` 也能跑后台自定义网络**：可以（给 `code=` 就是）——
> 这才是长训练自定义网络的**正确姿势**。同步的 `run_custom` 只适合短训练：
> 它受 10 分钟客户端超时限制，而且**拿不到 job 句柄 ⇒ 想停都没法停**。

### 4.5 图神经网络（GNN）：能跑，且观测面照旧

**能跑什么**：节点分类类的图任务（一行=一个节点、一个标签）。AI 写一个真的图卷积
（自己实现消息传递，用 `A_hat @ H @ W` 这种矩阵乘法即可——**不需要** PyG/DGL），
框架负责切分、训练、观测、存档。

```python
# run_custom 的 code：图网络只用多写一个 forward_graph
class Network:
    def build(self, n_in, n_out, *, nn):
        return MyGCN(n_in, 16, n_out)

    def forward_graph(self, model, ctx):        # ctx 里什么都有
        return model(ctx["x"], ctx["edge_index"], ctx["n_nodes"],
                     ctx.get("edge_weight"))
```

**建一份图数据**（`prepare_dataset` 加 `graph`）：

```jsonc
{"source": {"kind": "arrays", "X": [[...]], "y": [...]},
 "graph": {"edges": [[0,1],[1,2]], "directed": false},   // 或 edges_path: "edges.csv"
 "pipeline": {"steps": [{"key": "scale"}]}}
```

回执里会带**拓扑事实**（节点数/边数/度分布/孤立点）——图的坑大多在这几项上。

**四条要知道的**：

1. **节点掩码，不是切行**：图上的训练/验证按 `problem.masks()` 划分（同一张图、
   只对指定节点算损失）。切行会让边索引失效，而且训练节点会沿边"看到"验证节点
   ⇒ 分数乐观化。这与时序用 `time_split` 是同一类修正。
2. **不声明支持图的方法会被拒绝**（不是静默忽略拓扑）：`torch_mlp` 这类只吃表格的
   方法碰带图的数据会明确报"不支持辅助结构 ['graph']"。
3. **图任务不走交叉验证**：CV 按行切片会让边索引静默失真 ⇒ 明确拒绝（并在 diag 里
   说明为什么没跑）。
4. **图模型不能对"一批新行"预测**：前向需要整张图的边 ⇒ 会回可读理由；
   测试节点的预测已随运行产出（按 test 掩码对齐）。

> **做不到的（如实说）**：链路预测（样本是**边对**）与图分类（一行=一整张图）——
> 它们的标签单位不是"行"，与现契约的形状不同。今天支持的是**节点分类**这一类。

### 4.8 AI 调用体验（依据 mecha《AI调用体验-指导意见》逐条对账）

那份指导意见是**从使用者 AI 的实测里长出来的坑清单**。我们逐条对了一遍，
查出 6 处真缺口并全部补上（各配判据）：

| 指导意见 | 缺口的实际形态 | 现在的做法 |
|---|---|---|
| §3-1 **并发上限** | local job 是"每次 submit 新起线程、**不排队、无上限**" ⇒ AI 连提交十个训练就把机器打满，而它毫无察觉 | `BoundedSemaphore`（默认 4，`MLTB_MAX_JOBS` 可调）；**超额响亮拒绝**（`too_many_jobs`）；名额在任务**真跑完**后释放 |
| §3-2 **提交前写权预检** | 不预检 = "提交成功 → 查进度 → 发现失败"（AI 白等一轮，还可能把失败读成实验结论） | `authority.gate(side)` **只读预检**：LOCKED 下**同步**拒绝（`authority_locked`），且**不建 job** |
| §5 **描述里不许有实现词** | 管道一直在（`define_tool` 构造期校验），但装配点传的是**空表** ⇒ **纪律铺了却没启用**（比没铺更坏：它看起来"已经有守卫了"） | `BANNED_WORDS` 真词表；启用后立刻抓出 `submit_run` 描述里的"轮询" |
| §1-P1-5 **清零入口** | 配置跨会话残留，而**没有任何入口清零** ⇒ AI 在别人没收拾的台面上干活，"我用默认配置跑"会变成假话 | `clear_current_state`：逐键 `before`/`readback`，`n_cleared` 只数**真有值**的键 |
| §1-P1-6 **pick 投影** | 序列/清单类回执整坨灌进上下文 | 键路径投影（实测省 65%）；缺失键如实列 `_missing`；⚠ **必填键删不掉**（工具面契约），所以只装在"大负载不是必填键"的地方 |
| §4 **编排入口** | 一条工具一次往返 ⇒ "列方法→看参数→查数据集→看训练"要 4+ 次 | `run_queries`：一次往返跑一串**只读**查询；`output` 挂在**步里**、失败步给教学原因、首个失败即停、参数**预检可教学** |

**两处边界，如实标出**：

- `run_queries` **只读**：CodeAct 够得到的是内置动作 + `Surface` 里注册的查询，
  **不触达 command/tool 面** ⇒ 写操作仍要一条条经受控命令面（各自过闸、各自留痕）。
- 顺带修掉一个**描述与行为不符**的真缺陷：`describe_training` 的描述写着
  "留空则按最近落盘的 run 找"，而引擎把空 `run_id` 直接透传 ⇒ 一律
  `available=false`。AI 照描述省略参数，会得到"这次训练没有观测数据"这个**错结论**。
  现在真的按描述找（读磁盘挑**真有事件**的那次）。

**⚠ 两个名字改了（指导意见与宪章冲突）**：指导意见举例用的 `reset_config` /
`run_actions` **恰好都在 EL 的命令名表里**，而本仓宪章 R1 硬性禁止复制 EL 命令名
（判据是子串匹配，会当场红）。⇒ 采用它的**意图**、用 ML 自己的词汇：
`clear_current_state`（清零台面）/ `run_queries`（一次往返跑一串只读查询）。
判据 `test_static_ml_mecha_does_not_copy_el_command_or_state_names` 抓到的
——**这不是坏事，是那条宪章判据在正常工作**。

**⚠ 顺带查出一个更大的问题（已修）**：门禁用**脚本**方式跑 `test_*.py`，而多数
文件的入口是**手写判据清单** ⇒ 新写的判据忘了加进清单就**永远不进闸**。实测：
`test_ml_mecha.py` 有 **20 条**已定义判据从未被门禁执行（含 GNN 端到端、后台落盘、
训练观测面），其中一条**当时就是红的**（只在 pytest 下跑过，而门禁不看 pytest）。
⇒ 全部改成**内省收集**（定义即入闸），并加了一条元判据
`test_every_defined_judgement_is_actually_run_by_its_file` 防复发。

### 4.7 时序方法：外生变量

8 个时序方法里**只有 ARIMA/SARIMAX 数学上支持外生变量**（`supports_exog=True`），
其余 7 个（SES/Holt/HoltWinters/Theta/朴素趋势…）是单变量方法。数据带了外生列而
方法用不上时，**会在 diag 里如实披露**（`unused_features` + `unused_reason`）
——不再静默忽略（老契约下"时序忽略外生 X"曾是静默的，见 README 记的已知限制）。

### 4.6 自己组装预处理链（"自由的那半"）



默认链是**中位数填 → one-hot → 标准化 → 8:2 切分**。要换策略、加特征工程、
改切分比例，就给 `prepare_dataset` 一份 `pipeline` 声明：

```jsonc
{
  "steps": [
    {"key": "missing", "params": {"strategy": "mean"}},          // 换填充策略
    {"key": "ratio",   "code": "class Step(StepBase):\n ..."},   // 写自己的步骤
    {"key": "scale",   "params": {"mode": "robust"}},            // 换缩放方式
    {"enabled": false, "key": "feature_select"}                  // 跳过某步
  ],
  "split": {"test_size": 0.2, "stratify": true, "seed": 7}       // 指定切分
}
```

- **内置步骤**：`missing`（`strategy`: median/mean、`drop_threshold`）、
  `encode`（`mode`: onehot/ordinal）、`scale`（`mode`: standard/robust）、
  `feature_select`（`top_k`、`score`: mi/f、`seed`）、`split`；
- **自定义步骤**：写 `code`，里面 `class Step(StepBase)`，实现
  `apply(self, df, target, diag=False)` 返回 `(新表, 摘要)`；
  ⚠ 要按**训练集统计量**变换的（均值/分位数）**必须也写 `transform`**，
  否则新数据会被按它自己的统计量变换（**静默的错**）；
- **顺序就是你给的顺序**（不重排、不去重）；`enabled: false` 跳过该步；
- **划分口径以 `split` 为准**（`describe_dataset` 报的就是它，逐数据集为真）；
- **坏声明会报错**：未知步骤 / 未知键 / 坏取值 / 坏切分 / 代码语法错
  —— **都不静默忽略**（"设了不生效"是最坏的情况）。


> **神经网络（`torch_mlp`）现在能配的比层宽更多**（2026-10-03 扩面）：
> 结构 `hidden`/`activation`（relu·tanh·sigmoid·gelu·leaky_relu·elu）/`dropout`；
> 优化 `optimizer`（adam·adamw·sgd·rmsprop）/`lr`/`momentum`（仅 sgd）/`weight_decay`；
> 调度 `lr_schedule`（none·step·cosine）/`lr_step`/`lr_gamma`；
> 训练 `epochs`/`batch`/`val_split`/`seed`/`device`。
> 用 `describe_method("torch_mlp")` 看当前全量（含默认值与候选）。
>
> ⚠ **两个诚实约定**：① `momentum` 只对 `sgd` 有意义——给 adam 传非 0 值会**明确报错**，
> 不静默忽略（否则你会以为"我设了动量"而实际没有）；② **上了调度器之后，
> `describe_training` 的 `lr` 曲线是逐 epoch 的真实值**（会衰减），
> 不是参数里那个常量——所以"我设了 0.1"与"实际用的 lr"要看曲线说话。

> **长任务**：单次调用有 10 分钟上限（启动时自动配置）。更久的用 `submit_run` +
> `read_job`，AI 不会被卡住。**后台跑的神经网络训练会逐 epoch 报进度**
> （`read_job` 的 `progress` 形如 `{"frac": 0.72, "stage": "epoch 29/40"}`），
> AI 因此能判断"跑到哪了"，也能据 `describe_training` 的曲线决定要不要早停。
> 取消是**协作式**的：任务会在下一个检查点停下，
> 单次训练计算中途不可打断（这一点如实告知，不假装能打断）。

### 4.9 逐行负载、复数与"把模型拿回来"（NQS 需求的落地）

需求文档：`docs/需求-在ML工具里训练神经量子态.md`（一个里德堡原子阵列的使用者）。
他写下的三处卡点，逐条对应到下面三组能力；判据在 `tests/test_nqs_path.py`。

| 他卡在哪（原话） | 现在怎么做 |
|---|---|
| "复数振幅被弄成了实数" | 复数列**当场拒**并指路（以前是**静默丢虚部、回执还说成功**） |
| "变长位串没有地方放" | **逐行负载** `payload`：每个数组第 0 维 = 行数，dtype 原样保留 |
| "拿不到那个模型" | `run_custom` 写**完整 checkpoint**（含偏置）→ `checkpoint_detail` 查 → `eval_custom` 交给他的代码 |

**① 逐行负载（`payload`）**：有些任务的"一行"自带一份变长/复数的大数组（2^N 个复振幅、
采样的位串、逐原子特征）。它们既不是列、也不是"行之间的图" ⇒ 给一个明确的槽：

```jsonc
"payload": {
  "hdf5": {"path": "data.h5",              // 大数组/复数走这条（HDF5 原生支持复数）
           "datasets": {"amps": "/config/amps", "bits": "/config/bits"}},
  "arrays": {"n_atoms": [6, 8, 10]}        // 小数据内联（只有实数）
},
"target_kind": "custom"                     // 没有标准标签时写它
```

三条硬约定（违反**当场报错**，不裁剪、不错位）：第 0 维 = 行数；dtype 原样保留；
变长的维先 pad 再配 mask（`core.paddings.pad_rows`）。
图上多出来的列同理成为**多分量边特征**（`edge_attr`(E×F)）——耦合有 6 个物理分量时
不必压成一个标量。

**② 自定义任务（`target_kind="custom"`）**：标签就是负载里那些复数振幅、标准指标对它
**不成立**时：`y` 可以是 `None`、**必须**写 `Network.loss`；标准指标**不计算也不假装**
（diag 里写明理由），指标改由 `Network.metrics(model, ctx)` 每轮上报 ⇒ 写进 TensorBoard
⇒ `describe_training` **直接读得到**（查询面一行没改）。分组靠 tag 命名（`fid/ch0`、
`fid/ood`）。`Network.on_step(model, step, ctx)` 提供"步"的概念（预热：
"前 N 步先只训模长"）。

**③ 把模型拿回来**：训练结束写 `runs/<run_id>/checkpoint/{best,last}.pt`
（**完整 `state_dict`**，含 bias/LayerNorm —— 诊断产物 `nn_weights` 只存 `dim()>=2`，
**装不回来**），连同那段网络代码一起存（所以重建不依赖你还记得代码）。
`eval_custom(run_id=…, code=…)` 装载后**交给调用方的代码**：

```python
def evaluate(model, ctx):
    # ctx: payload（**可现场给新数据** = "换个没见过的 N 评估"）、meta、torch、nn、device
    return {"fid": 0.97, "speedup": 15.0}
```

**④ 设备真上卡**：`run_custom(device="auto")` 有卡就上卡（`torch_mlp` 一直如此，
自定义网络这条路以前**硬编码 CPU** ⇒ 46 万参数根本跑不完）。要求 cuda 而没卡会
**报错**，不静默回落（那会留下"审计说 cuda、实跑 CPU"的假记录）。

**⑤ 分组留出**：`{"group_by": "N", "holdout": [14, 16]}` ⇒ 整组留出到测试集。
随机切分做不到"尺寸外推"这件事（它会把 N=14 的一部分也放进训练），而且它顺手堵住
一整族**同源泄漏**。

> ⚠ **刻意没做的**：图级任务（"一张图 = 一个样本"）。按上面的重新表述，这类需求是
> "**一行 = 一个样本 + 附带负载**"，行级语义保住之后**不需要**图级任务
> ——需求者也明说不需要图分类。

## 5. 驾驶舱（只读监控）

AI 模式下，AI 界面会话头部有一个 **「◈ 监控」** 按钮：点它会在右侧栏打开监控面板
（也可以在右栏标签里找到「ML 监控」）。面板**只读**——它不能改任何东西。

### 5.1 三页各看什么

| 页签 | 看什么 |
|---|---|
| **飞行记录仪** | "谁在什么时候改了什么"：每条写事件一行（`#序号 / 谁 / 类型 / 原因`），展开看 `before → after` 全量 |
| **配置态** | 当前状态快照的现值 + 每键最后写入的归因（谁、第几条） |
| **运行记录** | 最近跑过什么：操作史里的运行（AI 跑过就一定有）+ 磁盘存档 `runs/`（跨重启可见） |

> "运行记录"里两个来源为什么可能不一样：磁盘存档只在**显式要求保存**时才写
> （AI 默认不落盘）。所以**存档为空不等于没跑过**——面板上写了这句提示。

### 5.2 `mode` 徽标的三种含义

面板右上角一直显示当前写权在谁手上：

| 徽标 | 含义 |
|---|---|
| **写权 AI**（紫） | AI 模式：只有 AI 通道能写 |
| **写权在人**（绿） | 本地 GUI 模式：只有人（界面）能写 |
| **全员禁写**（黄） | 维护态：谁都不能写 |
| **权威离线**（红） | 连不上后台权威（软件没在 AI 模式跑？或刚被切走） |

### 5.3 地址从哪来（为什么不用你配）

监控端口每次启动由系统分配，程序会把它写进项目根的运行期文件
（`.ml-monitor-port` 与 `.ml-mecha-runtime.json`）。面板**不问 AI、也不猜端口**：
它去问 dsh 自己的一个同源只读地址（`/ml-toolbox/monitor-url`），由插件读上面那个
运行期文件后回一个地址。读不到就显示"监控端点未知 + 重试"，**不会**回落到某个
"常见端口"（那等于把面板悄悄指向别人的服务）。

### 5.4 TensorBoard：训练过程的**全部面板**（多开一个窗口看）

上面三页是**软件自己的账**（谁改了什么、配置现值、跑过什么）。它们**看不到训练过程**
——loss 怎么走的、梯度有没有爆、哪层死了。那类"形状"信息我们**不自己画**，
交给 TensorBoard（它做了十几年，SCALARS / HISTOGRAMS / IMAGES / TEXT / PROJECTOR 都是现成的）。

**怎么发生**：神经网络的每个 epoch 结束时，训练记录器把已采集的量**实时写进事件文件**
``runs/<run_id>/tb/``。⇒ TensorBoard 指着那个目录，曲线就**逐 epoch 长出来**。

| 我们写的轴 | 内容 |
|---|---|
| SCALARS | `loss` · `val_loss` · `lr` · **`grad_norm`** · **`dead_relu`**（五条核心） |
| SCALARS（逐层） | `grad/<层名>`（每层一条）· `weights_norm/{first,last,update}` |
| HISTOGRAMS | `weights/<层名>`（权重分布） |
| TEXT | `layers/health`（逐层健康表：参数量 / 梯度均值 / 权重范数 / 死 ReLU 比） |
| IMAGES | `latent/frame`（表示演化的逐 epoch 帧，同一 PCA 坐标系） |

**⭐ 为什么 `grad_norm` 与 `dead_relu` 最值得先看**（依据成熟实现的结论）：
**总梯度范数是发现"梯度爆炸/消失"的单个最有用信号**；⚠ **要按趋势读，不要读单点**
——绝对值取决于模型/数据/batch，没有普适好值。看**形状**：稳定带宽内波动＝正常；
快速增大多个数量级＝要爆（常先于 loss 尖峰）；趋近零不动＝消失（常伴 loss 不再下降）。

**怎么打开**（两种都行，**都不需要你配端口**）：

1. **让面板起**：向监控端点发一条 `GET /dashboard`，它起一个 TensorBoard 辅进程并回 `{url}`，
   端口写进项目根 ``.tb-port``；再用浏览器打开那个地址（**多开一个窗口**，不挤侧栏）。
2. **自己起**：``tensorboard --logdir "runs/<run_id>"``（或 ``--logdir runs`` 看全部 run）。

**AI 也读同一份**（所以它能"边跑边研判"）：监控端点有两条只读路由 ——

| 路由 | 给什么 |
|---|---|
| `GET /latest?run_id=…` | **最新一轮**的数值（loss/val_loss/grad_norm/lr/dead_relu + 逐层梯度） |
| `GET /series?run_id=…` | **整条序列**（逐 epoch 曲线）+ 表格行（`rows`，面板附加页直接渲染） |

⇒ **一份数据两种消费者**：人看 TensorBoard 的界面，AI 读同样的数字。

**⚠ 三件如实说明**：

1. **事件写失败不会拖垮训练**（训练是主结果，图是附加）——但**失败会留痕**（`rec.tb_errors`），
   不静默吞掉；面板/AI 拿到的是"读不到 + 可读原因"，不是空数组假装"跑到第 0 个 epoch"。
2. **TensorBoard 没装也能训练**（它是 `neural` extra 的一部分）：装了才写事件文件。
3. **"界面显示得对"不是我们能保证的** —— 我们判的只有"**写出的能被正确读回、且与
   `artifacts.npz` 一致**"（`tests/test_tensorboard.py`）。这条判据是**外部依赖格式漂移**的那道闸：
   它变了，我们会红，而不是静默读空。


> 改了面板源码后要 **`cd dsh && npm run bundle` 并重启 AI 界面**（dsh 不热加载面板）。

## 6. 故障排查

### 6.1 启动相关

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报 `writer_lease_held` / "数据目录已被另一个写宿主占用" | 已经有一个实例在跑（或上次没退干净） | 关掉所有 ML Toolbox 窗口与控制台，确认真没有残留 `python` 进程后再启动。同一数据目录**同时只允许一个写者**（这是账本序号不重复的前提） |
| 报"已经有一个看门人在跑（pid=…）" | 同上，看门人级别 | 先关掉那个实例。若确认它已经是死进程，**直接重跑即可**（陈旧锁会自动接管） |
| `ModuleNotFoundError: No module named 'mecha'` | mecha 框架不在位 | `pip install -e <mecha 仓路径>`；或设环境变量 `MECHA_ROOT` 指向它 |
| `ModuleNotFoundError: No module named 'mcp'` | 缺 MCP SDK | `pip install mcp` |
| 界面报 `lightgbm`/OpenMP 相关崩溃 | 导入顺序被破坏（训练库必须先于 Qt） | 别自己拼启动脚本；用 `python launcher.py` 或 `python app_entry.py --gui` |
| 模式弹窗起不来 | 无图形环境 / Qt 装不上 | 绕过弹窗：`python app_entry.py --gui` 或 `--authority` |

### 6.2 AI 模式相关

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 日志说 "PATH 里没找到 dsh" | 没装 dsh 或不在 PATH | AI 模式仍可用（工具在、AI 只是没界面）。装 dsh 后重跑；或按日志里给的命令手动起 |
| 日志说"面板插件未构建/构建失败" | 没 Node.js，或 npm 装/构建失败 | 按日志提示装 Node.js，或手动 `cd dsh && npm install && npm run bundle`。AI 模式与工具**照常可用**，只是没有右栏面板 |
| 日志说"权威未就绪：端口文件还是上一次的旧值" | 上一次被强杀留下了陈旧端口文件 | 程序会自己等**新**端口（不会连死端口）并超时报错。重跑一次通常就好；持续如此看权威自己的日志 |
| 日志说"权威未就绪：端口 N 上还没有 HTTP 响应" | 权威起了但服务没 listen（端口被占/依赖缺失） | 看权威进程的输出（同控制台）。它自己的报错会说明原因 |
| 面板**空白**或一直"正在解析监控端点地址…" | ① 不在 AI 模式；② 权威刚被切走；③ host 半没挂上 | 确认是 AI 模式；点面板里的**重试**；再看 `dsh/README.md` 的排查。面板**不会**回落到默认端口（那会指向别人的服务） |
| 面板显示"监控端点未知：命令未返回监控地址" | **旧版面板的已知 bug**（地址经命令取、返回值形状读错） | **已修**：地址改走同源只读路由。**必须重建面板并重启 AI 界面**才生效：`cd dsh && npm run bundle`，再重跑 `python launcher.py`（dsh 不会热加载面板） |
| 面板拿到的是**上一次**会话的端口（一打开就"权威离线"） | 旧版按启动目录找运行期文件，可能读到**残留**描述符 | **已修**：看门人现在显式把数据根经 `MLTB_ML_ROOT` 告诉面板插件。重跑 `python launcher.py` 即可；手工起 dsh 时请自己设 `MLTB_ML_ROOT=<ML 仓根>` |
| 面板显示"权威离线"（红徽标） | 连不上后台权威 | 软件可能已经切回 GUI 模式，或权威崩了。切到 AI 模式重试 |
| AI 调用工具报**超时** | 单次调用超过 10 分钟 | 让 AI 改用 `submit_run` + `read_job`（提交后台任务） |
| AI 调用工具报"连不上" | 权威中途崩了/重启过（端口变了） | 重跑 `python launcher.py`（权威与 AI 界面同生命周期）。这是已知限制，见 §7 |

### 6.3 数据与权限

| 现象 | 原因 | 怎么办 |
|---|---|---|
| AI 读 CSV 报 `dataset_roots_required` | 没授权任何数据目录（**默认拒绝**，这是有意的） | 启动时显式授权：`python app_entry.py --authority --dataset-roots <目录>`（可重复）。不授权时合成数据/数组/内存表仍可用 |
| AI 读 CSV 报 `dataset_path_denied` | 路径在授权目录之外 | 用授权目录里的路径，或加授权 |
| AI 说写不进去 / `authority_locked` | 写权还在 LOCKED（刚起、闸没开完） | 等几秒重试；正常路径不该出现（选 AI 模式即授权 AI 写） |
| 找不到跑过的实验 | 磁盘存档只保存**成功且被要求保存**的运行 | 看驾驶舱「运行记录」页的"操作史"部分（AI 跑过就有）；或在 GUI 模式看历史面板 |

## 7. 已知限制（如实告知）

1. **权威重启后 AI 界面里的工具可能"在但用不了"**：这是 dsh 内置 MCP 客户端在
   streamable-http 上的已知未决行为。当前靠"权威与 AI 界面同生命周期"规避——
   出现时**重跑 `python launcher.py`** 即可。若频繁遇到，见下面 §7.1 的观测程序
   （它决定要不要上更重的自愈方案）。
2. **取消是协作式的**：任务在检查点停下，单次训练计算中途不可打断。
3. **任务编号（`job_id`）不跨模式**：切换模式会终止后台任务；跨模式/跨重启回看运行
   请用磁盘 `runs/`（或驾驶舱「运行记录」）。
4. **AI 模式下看不到图**：面板只给指标与元数据。要看图切回本地 GUI 模式
   （数据都在 `runs/<run_id>/`，历史面板能打开）。
5. **失败/取消的运行在 GUI 批量路径不落盘**：属既有行为；成功运行都在 `runs/`。

### 7.1 R1 手动观测程序（判断是否需要更强的自愈方案）

**为什么观测**：dsh 官方文档自己列了一条限制——HTTP 连接建立后，请求失败走 SDK 的
恢复机制而不是重建连接；"Streamable HTTP 的重连归属仍未决定"。所以要确认它**到底
会不会咬人**。

**步骤（约 3 分钟）**

1. `python launcher.py` → 选「AI 模式」。
2. 在 AI 界面里调一个只读工具（例如问"现在有哪些方法能用？"）→ 确认能拿到结果。
   记下项目根 `.ml-mecha-runtime.json` 里的 `mcp_port`（记作 **P1**）。
3. **在 AI 界面不退出的前提下**杀掉后台权威：
   `Get-Process python | Where-Object { $_.Id -eq <authority_pid> } | Stop-Process -Force`
   （`authority_pid` 见同一个文件）。
4. 重新起一台权威（同一目录）：`python app_entry.py --authority`
   → 它会拿到**新端口**（记作 **P2**，与 P1 不同）。
5. **不要重启 AI 界面**。回到会话里再调同一个只读工具。

**看结果**

| 看到什么 | 含义 | 该做什么 |
|---|---|---|
| 调用**成功** | 客户端已恢复 | 不用管，保持现状 |
| 工具**还在列表里但每次调用都失败**，**重启 AI 界面后立刻恢复** | **命中了那条死区** | 告诉开发者：该上自愈方案了（技术文档 §4 P3） |
| 工具**从列表里消失** | 重连次数耗尽后工具被移除 | 重启 AI 界面即可；记进排错表 |
| AI 界面自己崩了 | 与这条无关 | 看控制台输出 |

> 想少花时间也可以只做第 3 步（不重启权威）——但那时"工具在但用不了"是**正常**的
> （服务真的没了）。要区分"服务没了"和"死区"，**必须**做完第 4 步。
