## 1. 方法契约（`ml_toolbox/core/contracts.py`）

所有机器学习方法共享同一基类 `MLMethod`——这是"不同方法共享工具箱资源"的根本。

```python
@register                                  # core/registry.py 注册表
class MyMethod(MLMethod):
    name = "my_method"                      # 唯一键
    display_name = "我的方法"                # UI 显示名
    family = "ensemble"                     # 分组（UI 左栏按此归类）
    task = TASK_SUPERVISED                  # supervised|cluster|manifold|anomaly|timeseries
    target_kind = None                      # 'regression'|'classification'|None(双任务自适应)
    tags = ("fast",)                        # 搜索用；purposes 也由 tags 参与推导
    param_schema = [ParamSpec("alpha", label="α", kind="number", default=1.0, min=0)]

    def fit(self, X, y, cfg, diag=False) -> MLResult: ...
    def predict(self, X, result): ...       # 监督方法
    def inspect_pages(self, cfg) -> list[PageSpec]: ...   # 可选：声明专属核心图
```

**新增一个方法 = 实现一个类 + @register，不改框架任何代码（G1）。**

### 建模目的（purpose）维度

`task` 是"学习机制"轴，`purposes` 是"建模目的"轴（数模视角）。
9 个目的常量见 `contracts.PURPOSE_LABELS`：预测/判别/归因解释/分群/降维/
综合评价/异常检测/代理模型/参照基线。

- 默认由 `derive_purposes(task, target_kind, tags, family)` 推导（零成本继承）；
- 方法可 ClassVar `purposes=(...)` 显式覆盖；`m.purposes_of() / m.purposes_cn()` 读取；
- UI 方法库"用途"下拉按此筛选；tooltip 显示；
- 注意：tags 里的 `"baseline"` 是"该族默认起点"，不触发"参照基线"目的
  （只有 `family=="baseline"` 才触发，见 pitfalls L 备注）。

### 关键约定

| 约定 | 内容 |
|---|---|
| 参数 | 只通过 `cfg.resolve(param_schema)` 取；UI 覆写是运行级、不写回全局（P3） |
| 异常 | 方法内不抛出——`run_one` 捕获进 `MLResult.error`，遍历互不影响 |
| 诊断 | `diag=True` 才产出 `MLResult.diag`（结构化 dict）；默认零开销 |
| 评估 | 监督方法默认指标由基类 `evaluate()` 自动算（回归 rmse/mae/r2/mape；分类 acc/P/R/f1/auc） |
| 交叉验证 | 基类 `cross_validate()` 默认 k 折（分类自动分层），子类可覆写 |

## 2. 数据契约

- **单一数据入口**：`Dataset`（frame + target 列 + time 列），方法层禁止各自读文件；
- **管道**：`Pipeline.run(ds) -> DataSpec`，步骤链（缺失值→编码→缩放→筛选→划分），
  每步产出摘要 dict（含 `big_num` 大数字）存入 `spec.meta["chain"]`；
- **视图**：`DataSpec(X, y, train_idx, test_idx, target_kind, meta)` ——
  方法只消费这个，不感知文件与管道实现；
- **新数据变换**：`Pipeline.transform_new(frame, target)` 用 run() 冻结的统计量
  把新数据（如数模 test.csv）变换成与 `spec.X` 同构的特征矩阵（未见类别→全0列、
  缺失→训练期中位数、缩放→训练期参数、列自动对齐）；配合
  `method.predict(Xnew, result)` 实现"训练集选模型 → 测试集出预测表"闭环；
- **指纹**：`spec.meta["pipeline_id"]` = 管道配置哈希，实验记录可追溯。

## 3. 可视化契约（G2 高自由度所在）

### PageSpec —— 方法声明自己的检视页

```python
PageSpec(key="cm", title="混淆矩阵", kind="mpl",
         plot=lambda ax, result: ...,   # 纯 matplotlib，零 Qt（P1）
         hint="该方法不输出概率")        # 无数据时的语义化占位（模式 7）
```

- `kind`: `mpl`（plot 函数画到共享画布）/ `table`（消费 DataFrame 工件）/
  `text`（诊断文本）；`pg` 预留给 pyqtgraph 自适应组件；
- 方法未声明的页由 `runner.auto_pages(method, spec)` 按 task 兜底——
  **UI 永远有东西可显示，且兜底页与声明页走同一批 `methods/plots.py` 函数**；
- 共享页（指标/参数/诊断）由 `MLMethod.summary_pages()` 自动追加，方法无需声明。

### artifacts 键约定（UI 与导出按此消费）

| task | artifacts 键 |
|---|---|
| supervised | `y_true, y_pred, y_prob?, feature_importance?` |
| cluster | `labels, embedding, X_scaled` |
| manifold | `embedding, explained_variance_ratio?, labels?` |
| anomaly | `scores(越大越异常), labels(1=异常), threshold?` |
| timeseries | `t_true, y_true, forecast, ci?, horizon` |

## 4. 运行与持久化契约

- `runner.run_one / run_batch -> RunRecord`（方法+数据+配置+结果全留痕）；
- `persistence.save_record` 写 `runs/<run_id>/{record.json, artifacts.npz}`；
- **artifacts 支持嵌套结构**：`dict` 型工件（如 `nn_weights` / `nn_history`）存盘时
  按 `父__子__叶` 展平成 npz 键，`ui/history.load_run_record` 递归重组回 dict；
  多列 `DataFrame` 工件（如 `nn_layers`）拆 `<key>_values` + `_names`(+ 列数>1 时 `_cols`)；
- 对比视图排序依据 = `MLResult.primary_metric`（回归 rmse / 分类 f1 / 聚类 silhouette / 异常 auc / 时序 rmse）；
- **可选交叉验证**：`cfg.extras['cv_folds']>=2` 时 `run_one` 追加 `cv_<主指标>_mean/std`
  指标与 `diag['cv_scores']`（默认关，零开销 —— P3）；
- **实验可恢复**：`ui/history.py` 历史面板从 `runs/` 重建 `MLResult`
  （仅凭 artifacts 渲染检视图，不依赖 estimator），点载入即回看历史运行。

## 5. 入口脚本铁律（Windows 实测）

1. **lightgbm 必须先于任何 PyQt5 模块 import**（OpenMP 冲突 → access violation）。
   做法：入口处 `registry.load_builtin()` 放在 PyQt5 import 之前；
2. 离屏截图：CJK 字体显式加载、QMessageBox 打桩、grab 前同步 `canvas.draw()`；
3. 截图脚本的状态切换必须发生在截图 callable **内部**（构建列表与执行之间隔着主循环）。

### 检视页 kind 一览（PageSpec.kind）

| kind | 渲染 | 用途 |
|---|---|---|
| mpl | `plot(ax, result)` 画到共享 MplCanvas | 绝大多数核心图 |
| pg | `PGScatter`（pyqtgraph 滚轮缩放/拖拽） | 聚类/降维嵌入，大点量不卡（模式 5） |
| table | 消费 DataFrame 工件 | 指标/参数/特征表 |
| text | 只读文本 | 诊断产物 |
| nn_weights | 注册 builder（`ui/neural_pages.build_weights_page`） | 权重热图：层下拉 + 最终/初始/ΔW 视图 |
| nn_replay | 注册 builder（`ui/neural_pages.build_replay_page`） | 表示演化回放：epoch 滑块 + 播放 + 类纯度读数 |

**新页类型扩展（G2 自由度）**：方法层只声明 `kind` 字符串并把数据装进 `artifacts`；
UI 层用 `inspector.register_page_builder(kind, builder)` 注册工厂
`builder(result, spec) -> QWidget | None`（返回 None = 工件不足，显示 `spec.hint` 占位）。
方法层零 Qt，渲染逻辑全在 UI 层——新增一种可视化 = 注册一个 builder，不改框架。

### 神经网络可视化（方案 C：一半一半）

神经网络"中间发生了什么"仅靠 loss 曲线无法回答。方案 C 用 `TrainingRecorder`
（`methods/neural/recorder.py`，零 Qt 黑匣子）在训练循环里采集四类中间量，
经 `MLResult.artifacts` 契约化，UI 按 PageSpec 渲染五页：

| 页 | kind | 回答的问题 |
|---|---|---|
| 训练动态 | mpl | loss/val/lr/梯度范数/死 ReLU 五联曲线 |
| 权重热图 | nn_weights | 每层权重长什么样、训练前后如何变化 |
| 表示演化 | nn_replay | 类簇在第几个 epoch 分开（隐层→PCA 2D 回放） |
| 特征归因 | mpl | 哪些特征推高/压低预测（积分梯度，diag 开启时算） |
| 逐层健康 | table | 参数量/梯度范数/权重范数/死 ReLU 比例（按层） |


### UI 主区 tab（索引由 `indexOf(widget)` 集中管理，勿硬编码）

0 处理链 · 1 数据检视（特征相关热图）· 2 对比视图（表格）·
3 核心图对比（缩略画廊，遍历的视觉回报）· 4 方法检视

扩充方向（按 P5 边际成本递减原则）：Prophet 类时序、多目标优化（NSGA-II 用于数模）、
特征相关性热图的分级标注升级；Stacking/GaussianProcess/核岭回归已实现。
