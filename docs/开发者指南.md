# ML Toolbox 开发者指南

ML Toolbox 将机器学习方法库与 mecha 的操作者治理分开。ML 负责数据、方法、训练、优化和实验事实；mecha 负责命令、查询、写权、操作记录、Jobs、产物和宿主投影。

## 代码结构

| 区域 | 职责 |
|---|---|
| `ml_toolbox/core/` | 数据集、处理管道和实验核心模型 |
| `ml_toolbox/methods/` | 回归、分类、聚类、神经网络等方法 |
| `ml_mecha/engine.py` | ML 项目自己的实验协调器和命令实现 |
| `ml_mecha/assembly.py` | 创建软件、注册命令和查询、接入 Jobs 与账 |
| `ml_mecha/tools.py` | AI 工具投影和查询编排 |
| `ml_mecha/validator.py` | 数据、资源和运行规格校验 |

## 运行模型

`MLEngine` 是项目内部协调器，不是 mecha 的框架接口。公开动作注册到 mecha `CommandRegistry`，只读数据注册到 `Surface.QUERY`。同步命令、后台任务和工具投影共享同一命令实现，命令回执包含运行 id、指标、警告和结果引用。

数据集身份使用内容指纹；运行事实、训练观测和产物引用分别按其生命周期保存。后台任务由 mecha Jobs 管理，ML 负责并发上限、资源预算、checkpoint 和恢复语义。

## 修改原则

算法和实验语义留在 ML；不要把 ML 参数、方法名或指标名上提到 mecha。新增能力优先扩充项目命令或查询，再按真实共性提取框架机制。修改工具面时同时验证命令声明、查询注册、任务回执和 AI 可读结果。
