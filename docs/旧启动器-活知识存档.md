# 旧启动器（launcher.py）的**活知识**存档

> **为什么有这个文件**：2026-10-08 按《清理归一-口径》删掉了 `launcher.py`（834 行，旧看门人）。
> 它里面**只有几处**是"删掉就再也想不起来"的事实 —— 那些**不是**旧架构，
> 而是**踩出来的坑与实测出的常量**。这份文件把它们抽出来，避免"静默丢功能"。
>
> ⚠ **本文件记的是"为什么"，不是"怎么做"**：进程编排已整块归框架
> （`python -m mecha`），本项目不再自己编排。

## 1. ⭐ 就绪判据为什么是**双条件**（不能只判端口文件存在）

Windows 上 `terminate()` / `taskkill /F` **不跑** Python 的 `finally` ⇒ 强杀之后
`.mcp-port` 会**残留**。只判"文件存在"就会让启动方立刻去连**一个已死的端口**
（现象："起得来但看不见"）。

⇒ 必须三条一起用（今天的 `ReadySpec` 表达得下前两条）：

1. **spawn 前快照**端口文件（内容 + mtime）；
2. 轮询到**新鲜**（文件先消失过 / mtime 变新 / 内容变化）**且** `/mcp` 上有
   **HTTP 响应**（TCP 连得上还不够 —— 同一个端口上可能是别的东西在听）；
3. 超时 → **明确报错**，**不**静默退回某个默认端口。

⚠ **判据造法**（照《统一启动器-设计》§7.1.1③）：只造一个"没人听的旧端口文件"
**红不了** —— 那时是"探活"在拒绝它，把快照比较退化成 `return True` **照样绿**。
必须让**旧值那个端口也有人在听、也回 200**，此时唯一还能识别问题的只剩
"**这文件是 spawn 之前就有的**"。这才是那条假绿的真实形状。

⭐ **归属已迁**：这套现在是框架的 `ReadySpec(port_file=…, probe=…)`，
本项目在 `ml_mecha/mecha_site.py` 里声明（`ok_codes=()` = 任意 HTTP 响应算在听）。

## 2. 实测常量（**别丢**，丢了表现为"假失败"或"等太久"）

| 常量 | 值 | 为什么是这个值 |
|---|---|---|
| `TOOL_CALL_TIMEOUT_MS` | **600000**（10 分钟） | dsh 的 MCP 客户端默认 **60 s** ⇒ 长训练会被判"假失败"。⚠ 这条已随 overlay 生成**归框架**，但值本身要保住 |
| `READY_TIMEOUT` | 90.0 s | 权威首次导入 torch/lightgbm 慢；现在落在 `mecha_site.py` 的 `ready.timeout_s` |
| `EXIT_TIMEOUT` | 15.0 s | "先礼后兵"里等它**真退出**的上限（写租约随进程释放，等不到就会 `writer_lease_held`） |
| 面板退出时限 | 20.0 s | Qt 事件循环要时间；强杀会让 `finally` 不跑（A7/A56 同类教训） |

## 3. 环境与平台细节（删了就没人知道）

- ⭐ **`PYTHONIOENCODING=utf-8` 注入**：子进程 stdout 一旦**不是真控制台**
  （重定向到文件 / 被上层按管道捕获），编码就退回 **cp936** ⇒ 网络代码里一句
  `print("⚠ …")` 抛 `UnicodeEncodeError`，**让整个后台任务崩掉**（用户实测、本机可复现）。
  ⚠ 用 `setdefault` 语义（调用方显式给的优先）。
  ⭐ **已裁决归框架的 spawn 层**（所有子进程的共同需求）。
- **创建标志**：Windows 上子进程用 `CREATE_NEW_CONSOLE`（各占一个控制台窗口）。
- **dsh 面板插件产物是"拿到就能跑"的短板**：`dsh/lib/` **不入库**（提交构建产物会静默漂移）。
  旧实现做了三件事，**框架今天只做第 0 件**：
  0. `plugin_artifacts` 存在性检查（框架：缺了**响亮失败**）；
  1. ⚠ **`dsh/node_modules` 缺失 → 自动 `npm install`**（删 launcher 后**没人做了**）；
  2. ⚠ **产物比 `dsh/src/**` 新 → 自动 `npm run bundle`**（**新鲜度检测，框架没有**）；
  3. `node`/`npm` 不在 PATH 或构建失败 ⇒ **明确报错**，不静默假装成功。
  ⇒ ⚠ **这是删 launcher 后唯一"功能变少"的地方**（见 §6 未决）。
- **`--preload` 名单由 application 层给**：优化侧的读档能力是 `ml_toolbox.opt.persistence`
  **import 时**注册进 core 的槽，而 `ml_mecha` **不许** import opt（边界纪律）
  ⇒ 由启动方按名字传给面板进程。这条**接口仍然成立**（谁启动谁给名单），
  只是现在"启动方"是框架。

## 4. dsh 侧的实测坑（现在归框架，但别忘）

- ⚠ **MCP 端点的 patch 必须用 `- insert:` 包住**：裸 `- id: mcp-…` 会被 dsh 判
  "目标不存在"并**静默跳过**（组合树里根本没有它）。
- ⚠ **`failOnStartupError: true`** 让"连不上"变响，而不是留一个**空工具表**。
- ⚠ **永不占 `:3080`**（官方 dsh 的端口）⇒ 项目实例从 **3081** 起试。
- ⚠ **overlay 顺序 = 命令行顺序**，`--patch` 可重复；**同 id 的 patch 是整块替换**
  ⇒ 端口隔离层必须**照抄全部字段**（见 `dsh/cordis.project.patch.yml` 的注释）。
- **文件名稳定性**：`serverName: mltoolbox` 与 `/mcp` 路径决定工具前缀
  （`mcp__mltoolbox__*`）⇒ 框架生成时**别改名**。
