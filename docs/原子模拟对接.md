## 2. 交接文档必须回答的问题（写到哪算清楚，我就能接）

5. 能否并发跑多个实例（不同参数同时评估）？决定 batch 引擎能否真并行。

**B. 参数域**
6. 每个参数：名称 / 连续还是离散 / 上下界 / 是否对数尺度 / 精度要求（几位小数）。

**C. 目标**

**D. 附加条件（约束）**
10. 有哪些约束？等式/不等式？是"参数硬边界内"还是"仿真会主动拒绝不可行输入"？

**E. 预算与交付**
12. 总评估预算（次数或时间）？

## 3. 已知缺口与规避（彩排暴露的，诚实列出）

| 缺口 | 影响 | 现在怎么绕 | 是否实战前补 |
|---|---|---|---|
| 噪声无内置重复评估 | 单次噪声大时 best 不稳 | 交接文档给噪声水平；必要时 objective 内多次取均值 | 视噪声定 |
| 无真并行评估 | 若黑盒可并发，串行浪费墙钟时间 | 先串行跑通；确认能并发再加 `run_batch` 式并行 | 若单次>30s 且可并发则补 |
| 约束只有 censor/penalize/cEI | 复杂约束（等式、条件约束）不支持 | 边界内 + 惩罚；等式约束用参数化消元 | 视约束形态定 |
| GP-BO 高维（>6）退化 | 参数若很多，采集优化不准 | 优先 CMA-ES/TPE；或先敏感性降维 | 参数>6 时改默认引擎 |
| 黑盒若需"预热/初始化"脚本 | ProcessObjective 只覆盖"一次调用一次评估" | 若需常驻进程/多步交互，要加会话式 objective（未实现） | 视接口定 |

## 4. 拿到交接文档后的接入步骤

1. **填参数空间**：§2-B → `ParamSpace([ParamSpec(...), ...])`
2. **定调用模板**：§2-A → `cmd_template` + `parse` 正则（或 `result_file`+`score_key`）
3. **定方向**：§2-C → `minimize=`
4. **接约束**：§2-D → `constraint_signal=` + 选 `on_infeasible`
   （薄可行带用 `penalize`，可行占比中等用 `censor`+GP-BO `constrain`）
5. **定预算**：§2-E → `Budget(n_evals=..., time_limit=...)`
6. **选引擎**：小预算连续 → `gp_bo`；参数多/混合 → `tpe`；中预算 → `cma_es`
7. **先跑彩排同款**：用 `benchmarks/run_pulse_rehearsal.py` 的骨架，把假黑盒换成真命令，
   先 5 次评估验证"调用通、解析对、约束识别对"，再放开预算
8. **交付**：`OptRecord.best` + 平行坐标/响应面敏感性

**接入骨架**（交接文档到位后照填，预计 <30 行）：
```python
from ml_toolbox.core.contracts import ParamSpec
from ml_toolbox.opt import registry as oreg
from ml_toolbox.opt.contracts import ParamSpace, Budget
from ml_toolbox.opt.process import ProcessObjective
from ml_toolbox.opt.runner import optimize

oreg.load_builtin()
space = ParamSpace([ParamSpec("amp","幅度","number",0.7,min=...,max=...), ...])
obj = ProcessObjective(
    cmd_template=...,                 # ← §2-A
    space=space,
    parse=...,                        # ← §2-A 指标解析
    minimize=True,                    # ← §2-C
    constraint_signal="",             # ← §2-D
    on_infeasible="penalize",         # ← §3 策略
    timeout=...,                      # ← §2-A 单次耗时
)
rec = optimize(obj, oreg.get("gp_bo"), Budget(n_evals=...), seed=42)
print(rec.best)
```

## 5. 彩排已验证的实战结论（薄可行带硬约束）

`python benchmarks/run_pulse_rehearsal.py`（假黑盒：中文/科学计数法/θ∈[.85,1.15]硬约束/噪声）：
- **censored 会静默废掉 GP-BO**（可行点太稀，目标 GP 学不动，退化成随机，best 与随机搜索完全相同）；
- **自适应惩罚最强**（best 0.0034）：全量点喂 GP，地形信息利用充分——薄可行带默认推荐；
- **cEI 修复 warmup 死锁后优于随机**（0.1894），但薄带下不及惩罚；
- 结论：约束占比高（可行域薄）→ `on_infeasible='penalize'`；可行占比中等 → cEI。

> 这些是**假黑盒特定几何**下的结论。真黑盒的可行域形状未知，接入步骤 7 的
> 5 次预跑就是为了先探明它，再定策略。
